# 비서별 업무 흐름

[README.md](README.md) 의 절대 규칙이 먼저다. 각 표의 「현재」는 2026-11-02 기준이고, 바뀌면 여기를 고친다.

## 이지어드민 비서: 곡물도감

사람이 정한 범위: **일괄합포제외까지.** 송장출력은 불안정해 뺐고 합포 분할 화면에서 직접 한다.

| 번호 | 칸 | 누가 | 캐릭터 | 현재 |
|---|---|---|---|---|
| 1 | 일괄합포제외 | 사람이 누르고 상시 컴퓨터가 실행 | 저장 중 서류 들고 움직임 | 동작, 실제 저장 확인. 합포 분할 화면에서 불러오기를 해야 미리 보기가 생겨 1번 |
| 2 | 주문 미리 보기 | 비서 | 책상에서 일함, 송장 쌓임 | 동작 |

### 확인 필요

사람에게 보여 주는 것은 이것뿐이다. 나머지는 작업자가 육안으로 거른다.

- 60박스를 넘는 송장
- 모르는 상품
- 수량 없는 주문

이지어드민 응답의 `fail_list` 는 실패가 아니라 **미분할 목록**이다. 애초에 채우지 않은 주문이 대부분이다. 실제 반영 여부는 다시 검색해 대조한다.

### 지킬 것

- [ ] 비서 안 화면은 합포 분할 화면과 같아야 한다. 다른 점은 도우미가 필요 없다는 것과 흰 바탕뿐이다.
- [ ] 수령자 이름 대신 묶음번호를 보여 준다.
- [ ] 불러오기는 사람이 누를 때만 한다.
- [ ] 채운 뒤 탭이 새로 열렸으면 저장하지 않는다.

### 시간표 (만들 때)

- 월~금 09:00 또는 09:30, 14:20
- 수동 클릭은 항상 가능, 이미 수동으로 한 회차는 건너뜀
- 스케줄을 켤 때 폰 알림도 함께

## 이벗 비서: 맨소래담

사람의 판단은 **주문 매칭과 사은품 확인 둘뿐이다.** 나머지는 비서가 하는 것이 최종 목표다.

| 번호 | 칸 | 누가 | 현재 |
|---|---|---|---|
| 1 | 비젬 주문수집 | 비서 | 칸을 누르면 체크된 쇼핑몰·기간을 읽어 보여 주고, 사람이 버튼을 누르면 수집(`bizem_collect`)하고, 쇼핑몰별 수집 시각 대조가 정상이면 주문확정(전체)까지 이어 감. 수집 없이 확정만도 가능(`bizem_confirm`) |
| 2 | 비젬 주문 이벗에 넣기 | 비서 | 칸을 누르면 양식·대기 건수를 읽고, 사람이 누르면 양식 받기 → 나누기(`bizem_split.js`) → 맨소래담 이벗 등록까지(`bizem_import`). 받은 내용은 실행 PC 메모리에 3시간, 박스앤캔 파일(등록 못 한 맨소래담 포함)은 어느 기기에서나 「파일 받기」로 잠가서 내려받음(`filereq`·`fileres`). 이미 받은 주문이 섞이면 멈춤. 파일 선택으로 직접 하는 길도 유지. 실제 시험 전 |
| 3 | 이벗 주문수집 | 비서 | 칸을 누르면 맨소레담공식스마트스토어(14374) 신규·배송대기 건수를 읽고, 사람이 누르면 주문확인 체크 후 주문가져오기 한 번(`ebut_collect`). 이벗 함수 `go_NewOrderInsert` 를 그대로 부르고 확인창 문구(발주확인:○, 중복등록 경고)가 맞을 때만 확인. 끝은 `ins_btn_yn` 이 Y 로 돌아오거나 결과 칸(iframe1, site231proc) 로딩 완료로 봄. 실제 시험 전 |
| 4 | 주문 매칭 | **사람** | 화면 있음, 이벗 저장 전 |
| 5 | 묶음 및 출력확정 | 비서 | 읽기만 |
| 6 | 사은품 세팅 | **사람 확인** | 대상 계산, 메모 칸(`secretary/giftMemo`) 있음, 넣기 미구현 |
| 7 | 운송장 부여 | 비서 | 읽기만 |
| 8 | 출고처리 | 비서 | 읽기만 |
| 9 | 이벗 운송장전송 | 비서 | 미구현 |
| 10 | 비젬 송장업로드 | 비서 | 미구현, 비젬 연결 전 |

단계: 1~3 주문수집, 4~7 주문확정, 8~10 주문송장업로드.

### 지킬 것

- [ ] 판매처 맨소레담공식스마트스토어만 자동수집 대상이다.
- [ ] 수집이 끝나기 전에 다시 수집하지 않는다. 중복 등록된다.
- [ ] 수집 중에는 매칭하지 않는다.
- [ ] 출력취소하면 송장번호가 지워진다.
- [ ] 주문서삭제 메뉴는 다운로드만 쓴다.
- [ ] 시작 전에 행사 세부를 미리 묻지 않는다. 사람이 알려 준다.

### 비젬 화면 (2026-11-02 읽기 조사)

로그인 `www.bizesm.com/Home/Login` → 작업 화면 `partner.bizesm.com`. 메뉴는 창틀로 열림 (`addTabReload`, `iframe_코드`).

| 단계 | 화면 | 버튼 | 주의 |
|---|---|---|---|
| 주문수집 | \`REQ005MA\` | \`#btngetorderafterconfirm\` | **쇼핑몰에 발주확인 처리됨.** 되돌리기 어려움. 수집/클레임 선택 \`getOpt\`, 쇼핑몰 체크 표 |
| 주문확정 | \`REQ008MA\` | \`#btnSave\` 주문확정(선택) | 바로 옆 \`#btnDel\` 은 주문 삭제. 절대 누르지 않음 |
| 운송장인쇄 | \`REQ023MA\` | \`#preexcelFormDownload\` 양식다운로드 | 양식 \`0000_박스앤캔_코코나나양식\` = \`selexcelform\` 3880 |

- 주문수집: 화면의 체크·기간을 바꾸지 않고 `#btngetorderafterconfirm` → 비젬 확인창 확인을 한 번씩 누름. 진행창 `COM004PB` 가 끝나면 비젬이 버튼을 풀어 줌(`parent.resetButton`). 3분 안 재수집은 비젬이 막음. 공지창이 뜨면 확인창이 안 떠 멈추고 사람에게 알림. 자동 재시도 없음. 2026-11-03 실제 수집 성공: 13곳, 주문확정 대기 0→143건.
- 주문확정: `REQ008MA` 화면 기본 조건(미확정, 보류 제외, 최근 7일)으로 검색 → 부가 기능 `#btnAllOrderSave`「조회된 운송장 전체 확정」→ 확인창 문구(`전체 주문건을 주문확정`)가 맞을 때만 확인. 진행창이 강제 확정·취소를 물으면 누르지 않고 사람에게 넘김. 7일보다 오래된 대기나 보류는 남으므로 대기 건수로 대조해 알림. 가짜 화면으로만 시험, 실제 확정은 첫 실행 전.
- 양식 받기: 버튼 대신 비젬 `excelFormDownload` 가 만든 요청을 받아 `DateCheck` → `GetTB_ORDER_WAYBILLFORM` 순서로 보내고 내용을 받음. 화면 페이지 크기가 100장이라 쪽을 넘겨 합침(앞 쪽과 같은 줄은 뺌).
- 양식다운로드는 **비젬에 다운로드 기록을 남기고**, 다시 받으면 이미 받은 건수를 경고함 (\`GetWAYBIL_DWLD_DT_NOTNULL_CNT\`). 조사 삼아 받지 않음.
- 다운로드 요청에 페이지 번호와 크기가 들어감(기본 100장씩). 100건 넘을 때 전부 받는 방법 확인 필요.
- 맨소래담 판매처 이름: \`맨소래담-무신사\`, \`지그재그_맨소래덤\`, \`멘소래담_에이블리\` (철자 그대로). \`박스앤캔-에이블리\` 는 박스앤캔.
- 대표님이 준 양식(`ofc102edit_…xls`, 21열): 주문번호, 주문코드, 송장번호, 주문날짜, 발송날짜, **주문자이름(판매처가 들어감)**, 수취인, 전화번호, 휴대폰번호, 우편번호, 주소, 주문시요구사항, 배송시전할말, goodsidx, 상품명, 옵션1~4, 상품수량, 판매금액.
- 나누는 기준: 주문자이름이 맨소래담 판매처 3개와 정확히 같으면 맨소래담, 나머지는 박스앤캔. 처음 보는 값은 판매처별 건수로 보여 주고 사람이 확인.
- 고객 정보가 든 파일이라 Firebase 로 옮기지 않고 일하는 컴퓨터 안에서만 나눔.
- 실제 비젬 양식(2026-11-03, 69줄)을 나눈 결과 21칸 제목이 이벗 연동몰 열 정의 수와 같고, 주문자이름에 판매처가 그대로 들어감. 이벗 실제 업로드는 미시험.

## 업무 사건과 캐릭터 행동

새 업무를 붙일 때 이 표에 한 줄씩 늘린다. 왼쪽이 실제 데이터로 확인되지 않으면 오른쪽을 보여 주지 않는다.

| 실제 사건 | 어디서 아나 | 행동 |
|---|---|---|
| 상시 컴퓨터 신호 끊김 | `secretary/runner.ts` | 전원 커튼 |
| 로그인 풀림 | `secretary/sites/{id}.state` | 그 방 붉어짐 |
| 시동 후 읽는 중 | `jobs` `running` | 그 비서 work |
| 일괄합포제외 저장 중 | `jobs` `ez_split` `running` | 이지어드민 비서 work, 이름표에 단계 |
