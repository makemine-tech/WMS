# MakeWon Live WMS AI 개발 가이드 v1.0

AI 물류비서(`main/secretary*`)를 고치거나 늘릴 때 먼저 읽는다. 왜보다 어떻게를 우선한다.
업무 흐름은 [flows.md](flows.md), 그림·화면은 [design.md](design.md) 를 필요할 때 읽는다.

## 1. 최우선 목표

> 이 프로젝트의 최우선 목표
>
> "예쁜 WMS를 만드는 것이 아니다."
>
> "살아 움직이는 회사를 만드는 것이다."
>
> 모든 기능은 실제 업무를 캐릭터가 수행하는 것처럼 보여야 한다.

숫자를 보여주는 WMS가 아니라, 회사가 살아 움직이는 모습을 보여주는 WMS를 만든다.

| 숫자로만 보이던 것 | 이렇게 보여 준다 |
|---|---|
| 일괄합포제외 저장 중 | 이지어드민 비서가 일어나 서류를 들고 움직인다 |
| 로그인 풀림 | 그 비서의 방이 붉어진다 |
| 상시 컴퓨터 꺼짐 | 커튼이 닫히고 현황판이 빨강이 된다 |
| 출력할 송장 많음 | 책상 옆에 송장이 쌓인다 |

## 2. 절대 규칙

어떤 기능을 만들어도 어기지 않는다. 충돌하면 이 규칙이 다른 모든 규칙보다 앞선다.

- [ ] **가짜로 움직이지 않는다.** 캐릭터의 상태·말·일감 수는 실제 데이터에서만 온다. 일이 멈췄는데 일하는 모습을 보이면 사고다.
- [ ] **되돌릴 수 없는 작업은 사람이 누른다.** 저장·출력·전송은 건수를 보여 주고 사람이 확인한 뒤에만 한다.
- [ ] **자동 재시도 금지.** 저장·출력 요청은 실패해도 다시 보내지 않는다. 다시 묻는 것은 읽기(진행 확인 등)만 된다.
- [ ] **같은 송장번호를 두 번 출력하지 않는다.** 재출력 확인창은 거절한다.
- [ ] **수령자 이름·주소·전화는 Firebase 에 올리지 않는다.** 상시 컴퓨터 탭 안에만 둔다.
- [ ] **비밀번호·키를 코드·Firebase·git·확장에 저장하지 않는다.** 입력은 사람이 한다. 비서 화면에서 입력한 값은 공개키로 잠가 상시 컴퓨터로만 보내고(`secretary_login.js`), 한 번 쓰고 버린다. 기록·재시도 금지. 그 외 재로그인은 크롬이 채운 칸의 버튼을 한 번 누르는 것까지만 한다.
- [ ] **출력·저장 중에는 이지어드민 탭을 새로 열지 않는다.** 시동·점검·불러오기·헤드비서 새로고침이 모두 탭을 움직일 수 있다.
- [ ] **사람이 안 누른 일을 몰래 하지 않는다.** 페이지를 열었다고 자동으로 불러오지 않는다.
- [ ] **봇 탐지·보안문자를 피하지 않는다.**
- [ ] **거짓으로 보고하지 않는다.** 10장의 실제 확인을 안 했으면 안 했다고 쓴다.

## 3. 지금 시스템

새로 만들지 않는다. 있는 구조에 붙인다.

| 항목 | 실제 |
|---|---|
| 화면 | 일반 HTML + JS, 빌드 없음. `main/` 이 그대로 사이트 |
| 그림 | Canvas 2D 직접 그리기 (`secretary_office.js`) |
| 데이터 | Firebase Realtime Database |
| 호스팅 | Firebase Hosting (makewon.com), main 푸시 → CI 배포 |
| 시험 | `node --test` (`tools/tests/`), 외부 프레임워크 없음 |
| 상시 컴퓨터 | DMZOOT, 비서 전용 크롬, 이지에이전트 `C:\ez_PrintAgent` |
| 실행 PC | 한 번에 하나. 시작 버튼을 누른 컴퓨터가 맡을 수 있음(확장 필요), 그 탭을 닫으면 상시 컴퓨터가 다시 맡음 |

React·Phaser·TypeScript·Zustand·Tailwind·GSAP 를 넣지 않는다. 11장의 조건이 되면 그때 사람이 정한다.

### 파일

| 파일 | 역할 | 해도 되는 일 |
|---|---|---|
| `main/secretary_core.js` | 판단. 화면·Firebase 를 모름 | 순수 함수만. 사이트 목록, 상태 계산, 흐름도 |
| `main/secretary_runner.js` | 작업 실행. Firebase·탭은 `deps` 로 받음 | 명령 처리, 탭 보호 |
| `main/secretary.html` | 화면 + 헤드비서(`?run=1`) | 버튼, 흰 화면, `deps` 만들기 |
| `main/secretary_office.js` | 사무실 그림 | `rooms` 를 받아 그리기만 |
| `main/secretary_ez.js` | 이지어드민 미리 보기 계산 | 읽은 자료로 계산만 |
| `main/secretary_menso.js` | 맨소래담 미리 보기 계산 | 읽은 자료로 계산만 |
| `main/secretary_match.*` | 매칭 화면 | 저장 전 초안까지 |
| `main/ez_split.html` | 합포 분할 화면. `?remote=1` 이면 상시 컴퓨터로 전달 | 같은 화면 유지 |
| `main/ez_helper.js`, `main/ebut_helper.js` | 사이트 탭 안 도우미 | 정해진 명령만 |
| `tools/secretary_ext/` | 도우미를 넣는 크롬 확장 | |
| `tools/secretary_setup/` | 상시 컴퓨터 설치·점검 도구 | 읽기 전용 점검, 바꿀 때는 `y` |

### Firebase

```
secretary/
  runner      헤드비서 신호 (3분 끊기면 꺼진 것)
  sites       사이트별 로그인 상태
  jobs        작업 기록 ez_daily · ez_split · menso_read
  commands    시동 등 명령 (start · menso · match_read · match_search · bizem_check · bizem_collect · bizem_confirm · bizem_form · bizem_import)
  ezcall      합포 분할 화면 요청 (search · fill · reset · commit)
  loginKey    로그인 값을 잠그는 공개키 (헤드비서가 켜질 때마다 새로 만듦)
  loginreq    잠긴 로그인 값. 헤드비서가 받자마자 지움
  loginres    로그인 결과 (값 없음). 화면이 읽고 지움
  control     전체 멈춤
  campaigns   사은품 행사표
  match       매칭 자료·초안
wms_sync/groups/{gid}/
  ez_split          설정·실행 기록
  picking_ez/boxes  박스 기록 (읽기만)
```

`commands` 의 종류를 늘리면 `database.rules.json` 도 고치고 규칙을 따로 배포한다.

## 4. 구조 규칙

```
Firebase ─▶ secretary_core.officeRooms ─▶ OFFICE.update ─▶ 캐릭터
화면 버튼 ─▶ commands / ezcall ─▶ 헤드비서(runner) ─▶ 도우미 ─▶ 사이트
```

- [ ] 그림(`secretary_office.js`)은 Firebase·사이트를 모른다. `rooms` 만 받는다.
- [ ] 판단(`secretary_core.js`)은 그림·Firebase·화면을 모른다.
- [ ] 사이트 조작은 헤드비서만 한다. 화면이 사이트 탭에 직접 말하지 않는다.
- [ ] 읽기 명령은 `HELPER_CMDS`, 저장 명령은 `HELPER_WRITE` 에 있는 것만 나간다. 새 명령은 목록에 먼저 넣는다.
- [ ] 저장 명령은 페이지가 바뀌어도 다시 보내지 않는다.
- [ ] 화면 요청은 만료가 있다 (`RELAY_TTL`). 늦게 처리돼 저절로 저장되는 일이 없게 한다.
- [ ] 비서마다 파일을 나눠 키운다. `secretary_core.js` 에 업무 계산을 넣지 않는다.

## 5. 캐릭터 상태

모든 비서는 같은 4가지 상태만 쓴다. `officeRooms` 가 정한다.

| mode | 언제 | 화면 |
|---|---|---|
| `off` | 헤드비서 신호 끊김 | 커튼, 퇴근 |
| `idle` | 대기 | 평소 동작 |
| `work` | 그 비서의 작업이 실제로 진행 중 | 빠른 걸음, 초록 띠 |
| `alert` | 로그인 풀림, 멈춘 작업 | 붉은 방, 붉은 띠 |

- [ ] 새 상태를 늘리지 않는다. 필요하면 사람에게 묻는다.
- [ ] 로그아웃은 `alert` 이지 `off` 가 아니다.
- [ ] 다른 비서의 작업으로 움직이지 않는다.

## 6. 동작

대본은 `CAST` 의 `script` 에 쓴다. 필수 동작은 7개다.

| 동작 | 코드 | 현재 | 반복 |
|---|---|---|---|
| Idle | `stand`, `sit` | 있음 | 반복 |
| Walk | `walk` + `x` | 있음 | 도착까지 |
| Typing | `sit` + `type` | 있음 | 반복 |
| Coffee | `sit` + `sip` | 있음 | 반복 |
| Pickup | `box`, `sheet` 들기 | 들고 다니는 것만 | 1회 |
| Put | 없음 | 만들 것 | 1회 |
| Talk | 없음 (`point` 로 대신) | 만들 것 | 반복 |

- [ ] 앉기는 자리(`seat`)에서만 한다. 다른 곳이면 걸어간 뒤 앉는다.
- [ ] 상태가 바뀌어도 순간 이동하지 않는다.
- [ ] `prefers-reduced-motion` 이면 움직이지 않는다.
- [ ] 8번째 동작을 만들기 전에 있는 동작으로 표현되는지 먼저 본다.

- [ ] `tools/tests/` 시험

## 8. 체크리스트: 새 업무 추가

1. [ ] 사람이 하는 순서를 묻는다. 한 메시지에 질문 하나, 단답형.
2. [ ] 읽기 전용으로 건수만 계산해 흐름도에 보여 준다.
3. [ ] 실제 데이터로 사람이 하는 일과 맞춰 본다.
4. [ ] 사람이 누르는 저장 버튼을 만든다. 건수를 보여 주는 확인창, 실행 전 재확인, 실행 후 대조를 넣는다.
5. [ ] 소량으로 실제 시험한다.
6. [ ] 안정된 뒤에만 자동을 검토한다. 사람이 정한다.

흐름도 번호 순서대로 한 단계씩 끝낸다. 다음 단계 얘기를 미리 꺼내지 않는다.

확인창은 `confirm` 을 쓰지 않는다. 다른 탭을 보고 있으면 저절로 거절되므로 화면 안 창(`askPage`)을 쓴다.

## 9. 코딩 규칙

- [ ] 주변 코드와 같은 모양으로 쓴다. `var`, 함수, 짧은 이유 주석.
- [ ] 임의의 숫자는 이름을 붙인 상수로 둔다 (`RELAY_TTL`, `PRINT_IDLE`).
- [ ] 새 페이지에 `/mm_copy.js` 를 넣는다.
- [ ] 화면에 넣는 값은 `esc` 를 거친다.
- [ ] 안 쓰는 코드를 남기지 않는다. 일부러 꺼 둔 것은 이유를 주석으로 쓴다.
- [ ] 화면 글·보고·주석은 한국어.

## 10. 작업 끝내기

- [ ] `node --test tools/tests/*.test.js` 통과. 고치는 동작은 시험을 먼저 만들어 실패를 본다.
- [ ] `secretary_core.js` 의 `PAGE_VER` 올림. 헤드비서가 작업이 없을 때 스스로 새로고침한다.
- [ ] main 에 푸시. 다른 세션도 main 에 쓰므로 먼저 맞춘다.
- [ ] 사이트에 실제로 올라갔는지, `secretary/runner` 의 `ver` 가 바뀌었는지 확인.
- [ ] 규칙을 고쳤으면 `firebase deploy --only database`.
- [ ] 설치 도구를 고쳤으면 `tools/secretary_publish.ps1`. 개발 노트북에서는 상시 컴퓨터 도구를 실행하지 않는다.
- [ ] 실제로 확인한 것과 못 한 것을 나눠 보고한다.
  - 설치된 버전이 아니라 **실행 중인** 프로그램을 본다.
  - 가짜 응답 시험은 「가짜 응답으로 확인」이라고 쓴다.

## 11. 나중에 검토할 것

아래가 모두 맞을 때 사람이 전체 맵(Phaser 등)으로 옮길지 정한다. 지금은 만들지 않는다.

- 비서 흐름이 실제 업무에서 안정됨 (이지어드민·이벗 끝까지)
- 창고·지게차처럼 현재 방 구조로 표현이 안 되는 공간이 필요함
- 수십 명이 동시에 움직여 Canvas 직접 그리기가 느려짐

후보: 대표실·사무실·회의실·창고·출고장·휴게실 맵, 지게차와 택배기사, 음성 명령, 알림, ERP 연동, AI 보고서.
