# 곡물도감 합포 분할 (이지어드민 비서 1호) — 설계서

- 작성일: 2026-10-27
- 상태: 설계 승인됨 (대표님, 2026-10-27 대화)
- 큰 그림: 업체·사이트별 캐릭터 비서 자동화의 첫 번째. 이 페이지가 나중에 「이지어드민 비서」가 맡는 일이 된다.

## 1. 목적

이지어드민에 들어온 공급처 「곡물도감」 주문은 매일 「일괄합포제외」로 송장을 나눠야 한다.
이지어드민 자동 합포제외는 자주 틀리고, 그날 주문량·작업 인원에 따라 나누는 정도를 바꿔야 해서 지금은 사람이 하나하나 보고 나눈다.

이 일을 다음처럼 바꾼다.

1. 주문 전체를 우리 페이지로 읽어 와서
2. 「작업 난이도」 눈금 막대 하나로 분할 정도를 고르고 (예상 소요시간·택배비·포장비를 보면서)
3. 틀린 것만 고친 뒤
4. 이지어드민 화면에 분할을 자동으로 채우고
5. 대표님이 이지어드민 화면에서 확인하고 「일괄합포제외」를 직접 누른다 (안정되면 이것도 자동).

성공 기준:
- 매일 분할에 드는 시간이 눈에 띄게 줄어든다.
- 「기존대로」 결과가 피킹이지 박스 기록과 대부분 일치한다 (확인 필요 건은 맨 위에 따로 나온다).
- 이지어드민에 잘못 반영되는 주문이 없다 (어긋난 주문은 건너뛰고 알린다).

## 2. 확인된 사실 (2026-10-27 실제 화면·데이터)

### 이지어드민 일괄합포제외 화면 (`ga89.ezadmin.co.kr/template40.htm?template=DG00`)
- 검색 조건: 발주일, 공급처(곡물도감 = `str_supply_code` 20016) 등. 검색 버튼 `#search`.
- 결과 표 `#grid1` 한 줄 = 주문 안의 상품 하나. 칸(td class):
  `recv_name`(수령자) · `seq`(관리번호) · `collect_date` · `shop_name` · `product_id`(상품코드) · `supply_name` · `product_name` · `options` · `qty` · `pack_check`(체크+수량 입력) · `divide_pack_no`(정해진 박스 번호) · `divide_pack`(복수제외/초기화) · `do_divide`(제외실행) · `pack_seq`(합포 묶음번호) · `product_seq`.
- 분할 표현: 줄마다 「박스 번호(수량)」. 1번 박스 = 원래 송장에 남는 것.
- 「일괄합포제외」 버튼(`#divide_pack_all`) → 확인창 → `function.htm` 에 `template=DG00, action=drop_pack_all, info_all=…` 전송.
  `info_all` 한 묶음 = `묶음번호-상품seq:상품코드:수량/…-1번박스/2번박스/…` (박스 안은 `상품seq:수량,…`). 서버가 상품·수량 변동을 다시 대조한다.
- 오늘(발주일 10/27) 곡물도감: 346건, 730줄. 상품 1개 주문 62건, 2~7개 섞인 주문 284건.
- 상품명에 입수와 ★(= 칸 수)가 붙어 있다. 예: `서리태 가득콩물 30입 [곡물도감]★★`.

### 피킹이지 박스 기록 (`wms_sync/groups/makechango/picking_ez/boxes`)
- 614개 구성의 박스 크기: 45 230 · 60 147 · 30 117 · 15 76 · 「1」 33 · 45추가 3 · 60추가 8.
- 키 = `boxKeyOf(items)` (picking_ez.html) = 「로케이션|상품명|수량」을 정렬해 이은 문자열의 해시.
- 송장 PDF 상품명 = 이지어드민 상품명에서 ★와 끝 공백을 뺀 것. 로케이션은 전부 `—`.
  → **이지어드민 주문으로 같은 키를 만들 수 있다.**
- 규칙 「본품 칸 합 + 소형 있으면 1칸」을 현재 작업 199개 구성에 대 보니 177개(89%) 일치. 어긋난 것: 소형만 있는 주문(기록 15), 오리진케어 상품(기록 30·1), 소형이 여백에 들어가 한 칸 덜 든 경우.

### 하루 흐름
1. 이지어드민 일괄합포제외 화면에서 곡물도감·오늘 발주일로 검색 → 도우미 즐겨찾기 누름.
2. 도우미가 표의 줄을 읽어 우리 페이지로 보냄.
3. 우리 페이지에서 막대를 움직이며 송장 수·예상 소요시간·택배비·포장비 확인.
4. 필요하면 묶음별·주문별로 고치거나 체크 해제.
5. 「이지어드민에 채우기」 → 도우미가 줄마다 박스 번호를 채움 (저장 안 함).
6. 대표님이 이지어드민 화면에서 확인하고 「일괄합포제외」를 직접 누름.
7. 안정되면 「확정까지 자동」 스위치를 켜서 6번도 도우미가 함.

## 4. 분할 계산 (`ez_split_calc.js`, 화면과 떨어진 순수 계산)

### 4.1 상품 구분 (상품명으로 자동)
- **본품**: `(15|30|45|60)입` 이 있는 상품. 1개 = 완제 박스 1개. 칸 = 15입 1 · 30입 2 · 45입 3 · 60입 4.
- **소형**: 그래놀라(`Granola`, `C 그래놀라 … PACK`), 스타터팩(`S `, `N1 `). 박스 여백에 넣는다.
- **오리진케어·셀시어스** (당쉼, `1병_`, OTG, 셀시어스OTG): 나누지 않고 원래 주문 그대로 둔다. 섞인 주문은 「확인 필요」에 올린다.
- 이름 정리: ★ 제거, 앞뒤 공백 제거 → 피킹이지 상품명과 같은 꼴.

### 4.2 「단위」
주문 하나를 본품 단위(완제 박스 1개씩)와 소형 묶음 하나로 편다. 예: 서리태30×2 + 그래놀라 40 → [서리태30, 서리태30, 소형(그래놀라40)].

### 4.3 막대 왼쪽 끝 = 전부 분리
- 본품 단위 하나 = 송장 하나 (같은 상품 2개도 2장).
- 소형은 칸이 가장 작은 본품 송장에 같이 넣는다.
- 예외: 본품이 서리태 60입뿐이면 소형은 따로 송장 하나(15박스).
- 소형만 있는 주문은 그대로 한 장.

### 4.4 막대 오른쪽 끝 = 전부 합포
- 송장 하나에 4칸(60박스)까지. 송장 수가 가장 적게 되도록 칸 큰 것부터 채운다 (first-fit decreasing).
- 소형은 남는 칸이 있는 송장에 넣는다 (남는 칸이 없으면 1칸을 차지).
- 서리태 60입 예외는 왼쪽 끝과 같다.

### 4.5 막대 중간
- 왼쪽 끝에서 시작해서, 모든 주문의 「두 송장 합치기」 후보 중
  **(줄어드는 택배비) ÷ (늘어나는 작업시간)** 이 큰 것부터 하나씩 적용한다.
- 막대 눈금 n = 앞에서부터 n번째 합치기까지 적용. 오른쪽 끝 = 더 합칠 수 없을 때.
- 같은 입력·같은 눈금이면 결과가 항상 같다 (무작위 없음). 값이 같으면 묶음번호 순.

### 4.6 「기존대로」
- 주문마다, 나뉜 조각이 **모두 피킹이지 기록에 있는 구성**인 나누기 중 송장 수가 가장 적은 것.
- 주문당 단위가 많아 경우의 수가 클 때는 상한(본품 단위 10개)을 두고, 넘으면 「확인 필요」.
- 그런 나누기가 없으면 「처음 보는 구성」으로 「확인 필요」에 올리고, 일단 오른쪽 끝 결과를 넣어 둔다.
- 막대 위 한 점이 아니라 「기존대로 맞추기」 버튼. 그 숫자를 막대 숫자 옆에 같이 보여 준다.

### 4.7 송장 하나의 박스 크기
1. 피킹이지 기록에 그 구성이 있으면 기록값.
2. 없으면 규칙: 소형만 → 15. 그 외 → (본품 칸 합 + 소형 있으면 1) × 15.

### 4.8 막대 옆 숫자
- **송장 수**
- **예상 소요시간** = Σ 송장별 처리 시간.
  - 구성별 시간(입력한 것)이 있으면 그 값.
  - 없으면 등급 기본값: 완제 단독(포장비 300 등급) / 믹스 2칸 이하(1000) / 믹스 3칸 이상·60입 단독(1500). 기본 초는 설정에서 입력.
- **택배비** = Σ 박스 크기별 단가 (15·30·45·60 단가는 설정에서 입력).
- **포장비** = Σ `p9_fee.js` 곡물도감 포장비. 소분포장(300원)은 나누기와 무관해서 따로 한 줄.

## 6. 화면 (`ez_split.html`)
위에서 아래로:
1. 연결 표시: 🟢 이지어드민 연결됨 / ⚪ 연결 안 됨 · 불러온 주문 수·시각 · 도우미 즐겨찾기 안내.
2. 눈금 막대 (왼쪽 「작업 쉬움 · 전부 분리」 ↔ 오른쪽 「송장 최소 · 전부 합포」) + 송장 수·예상 소요시간·택배비·포장비. 옆에 「기존대로」 숫자와 「기존대로 맞추기」.
3. ⚠️ 확인 필요 (맨 위 고정): 처음 보는 구성 · 오리진케어 섞임 · 이지어드민에서 이미 나뉜 주문 · 경우의 수 상한 초과.
4. 구성별 묶음 표 (피벗): 「구성 → 나눈 결과(박스 크기별 송장) · 건수 · 1송장 시간」. 묶음 단위로 결과 바꾸기·체크 해제, 펼치면 수령자별 주문.
5. 설정: 박스별 택배비 단가 · 등급별 기본 처리 시간 · 「확정까지 자동」 스위치(처음엔 꺼짐, 슈퍼관리자만).
6. 「이지어드민에 채우기」 버튼 + 결과(채운 건수·건너뛴 건과 이유).

접근 등급: 관리자 이상 (`wms_access.js`). 메뉴 등록 `wms_pages.js`, 카피라이트 `/mm_copy.js`.

## 7. 이지어드민 도우미 (`ez_helper.js`)
- 실행: 즐겨찾기 `javascript:` 로 `https://makewon.com/ez_helper.js?v=…` 를 불러온다. `ezadmin.co.kr` 탭에서만 동작.
- 이벗 도우미(`ebut_helper.js`)와 같은 틀: 버전 관리(다른 버전이면 끄고 새로), postMessage 허용 주소(ALLOW) 검사, 상태 말풍선.
- 명령
  - `ping` → { ok, ver, page: DG00 인지 }
  - `read` → 현재 `#grid1` 의 줄 전부 { recv, seq, pack_seq, product_seq, product_id, name, options, qty, divided(이미 나뉨 여부) }
  - `fill { packs: [{ pack_seq, lines: [{ product_seq, product_id, qty, boxes: [{ no, qty }] }] }] }`
    - 채우기 직전에 표를 다시 읽어 묶음·상품·수량을 대조. 다르면 그 묶음은 건너뛰고 이유를 돌려준다.
    - 이미 나뉜 묶음은 건너뛴다.
    - 대표님이 손으로 할 때와 같은 화면 조작(체크·수량 입력·「제외실행」)으로 채운다 → 결과가 이지어드민 화면에 그대로 보인다.
    - 저장하지 않는다.
  - `commit` (「확정까지 자동」 켰을 때만) → 「일괄합포제외」 실행. 확인창은 도우미가 대신 승인. 서버 응답의 실패 목록을 돌려준다.
- 「제외실행」이 실제로 어떻게 박스 번호를 매기는지(행 단위 함수)는 구현 첫 단계에서 화면 코드로 확인하고, 화면 조작으로 안 되는 부분만 같은 함수를 직접 부른다.

## 8. 기록 (Firebase `wms_sync/groups/{gid}/ez_split`)
- `settings`: 택배비 단가, 등급별 기본 시간, 자동 확정 스위치.
- `times/{boxKey}`: 구성별 1송장 처리 시간 (입력한 것).
- `days/{YYYY-MM-DD}/{runId}`: 불러온 시각·주문 수, 막대 위치, 숫자 4개, 「기존대로」 숫자, 채운 건수, 건너뛴 건과 이유, 확정 여부·실패 목록.
- 데이터베이스 규칙(`database.rules.json`)에 `ez_split` 경로 추가 (picking_ez 와 같은 권한).

## 9. 안전장치 정리
- 확정(「일괄합포제외」)은 기본적으로 사람이 누른다. 자동 확정은 스위치 + 슈퍼관리자.
- 읽은 뒤 이지어드민에서 바뀐 주문은 채우지 않는다 (도우미 대조 + 이지어드민 서버 대조 두 겹).
- 이미 나뉜 주문, 오리진케어 섞인 주문은 건드리지 않고 알린다.
- 애매한 것은 추정으로 넘기지 않고 「확인 필요」 맨 위에 올린다.
- 도우미는 makewon.com 에서 온 요청만 받는다. 비밀번호·키를 쓰거나 저장하지 않는다.

## 10. 시험
1. **계산 단위 시험** (Node, `ez_split_calc.js`): 양 끝·중간·서리태 60 예외·소형만·오리진케어 섞임·같은 상품 여러 개.
2. **실데이터 시험**: 10/27 곡물도감 346건(이지어드민에서 읽은 줄)으로 「기존대로」를 돌려 피킹이지 기록과 일치율을 숫자로 낸다.
3. **포장비 회귀 시험**: `p9_fee.js` 로 바꾼 뒤 정산 엔진 9월 결과가 그대로인지 (포함가 55,807,950 등).
4. **채우기 시험**: 실제 이지어드민 화면에 채우기만 하고 확정은 누르지 않음. 대표님이 화면으로 확인.
