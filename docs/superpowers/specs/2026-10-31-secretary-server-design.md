# 비서 서버 (사이트별 업무 비서 + 창고 PC 인쇄 전용) — 설계서·검증 계획

- 작성일: 2026-10-31
- 상태: **초안, 대표님 결정 대기.** 서버 구입·구현·실제 송장 부여는 하지 않았다.
- 이 문서의 역할: 서버를 들일지 결정하는 근거. 7장 검증을 통과하기 전에는 구현하지 않는다.
- 이어지는 문서: [곡물도감 합포 분할 설계서](2026-10-27-ez-split-design.md)

## 1. 목적

지금은 대표님 크롬에서 북마크 도우미를 눌러 이지어드민을 조종한다. 이것을 다음처럼 바꾼다.

| 일 | 지금 | 바뀐 뒤 |
|---|---|---|
| 사이트 로그인 유지 | 대표님 크롬 | 로그인 비서가 점검·재로그인·보고 |
| 합포제외 → 송장 부여 → PDF | 대표님이 페이지 조작 | 일정에 따라 업무 비서가 진행 |
| PDF → 피킹이지 등록 | 2단계 자동수집 버튼 | 업무 비서가 등록 |
| 그룹 인쇄 | 창고 PC | **그대로 창고 PC** |
| 운영 | 대표님이 직접 | 비서 관리 화면에서 일정·상태·멈춤 관리 |

성공 기준:

1. 대표님이 손대지 않아도 정해진 시각까지 창고 PC 그룹 인쇄 화면에 송장이 올라와 있다.
2. 잘못 부여된 송장, 두 번 등록·두 번 출력된 송장이 0건이다.
3. 애매하면 멈추고 보고한다. 조용히 넘어가는 일이 없다.
4. 서버가 죽어도 지금 방식(북마크 도우미)으로 바로 일할 수 있다.

## 2. 이번에 확인한 사실

이 PC(TOOZ-GRAM)의 이지에이전트 설치 폴더와 로그(2026-10-17~31), 저장소 코드를 **읽기만 해서** 확인했다.

### 2.1 이지에이전트

- 버전 1.1.9, .NET Framework 4.7.2 **윈도우 프로그램**이다. 윈도우 서비스가 아니라 `HKCU\...\Run` 으로 사용자 로그인 때 뜨고 지금 세션 1에서 돈다. 포트 45271 을 연다.
- `updater.exe` 가 함께 있다. 프로그램이 스스로 바뀔 수 있다는 뜻이다.
- 설치 폴더에 `ChromeHeadlessShell`, `PuppeteerSharp.dll`, `PdfiumViewer.dll`, `Spire.Pdf.dll` 이 있다.
- 로그에 남은 출력 한 묶음의 순서:

```
[페이지→에이전트] initPrint
[페이지→에이전트] print_start { file: https://ga89.ezadmin.co.kr/data/clf/…_20017_….html, printer: "BIXOLON SLP-D 420", template_seq: "5" }
  generate pdf file → PdfFile\YYYY-MM-DD\…_20017_….pdf 생성 (약 4초)
  pdf 생성 완료
  pdf print start → pdf print end (약 8초)
[에이전트→페이지] print_result "2"
[페이지→에이전트] print_end
```

- PDF 의 Producer 는 `Skia/PDF m128` 이다. 이지어드민이 만든 HTML 을 에이전트 안의 크롬이 PDF 로 바꾼다는 뜻이다.
- **PDF 는 프린터로 보내기 전에 이미 만들어진다.**
- 14일 치 로그의 `print_start` 는 376건이고 `print_result` 는 전부 2였다. 오류는 로그 파일 사용 중 4건뿐이다. 하루 최대 106묶음이다.

### 2.2 「BIXOLON SLP-D 420」의 정체 (설계를 크게 바꾸는 사실)

```
이름  BIXOLON SLP-D 420
드라이버  Unidocs ezPDF Builder 7
포트  ezPDF Builder 7 Port:
```

이 PC의 「BIXOLON SLP-D 420」은 실제 라벨 프린터가 아니라 **이름만 빅솔론인 가상 PDF 프린터**다. 376건 중 362건이 이 이름으로 나갔다. 물리 프린터로 가는 포트가 없으므로 구조상 종이가 나올 길이 없다.

즉 **「프린터 없이 이지에이전트로 PDF 만 받기」는 이미 이 PC에서 2주 동안 운영 중인 방식**이다. 남은 질문은 「가능한가」가 아니라 「사람이 없는 서버에서도 그대로 되는가」이다. 다만 13건은 Xprinter, 1건은 삼성 프린터로 나갔다. 프린터를 잘못 고르면 진짜 종이가 나온다.

### 2.3 도우미 (`main/ez_helper.js`)

- 비밀번호 없이 탭의 로그인을 쓰고, 이미 재사용하기 좋은 명령을 갖췄다: `search`·`read`·`fill`·`reset`·`commit`·`printPrep`·`printGo`·`printStatus`·`printEnd`·`printClose`.
- `window.__mkwEzHelper` 로 직접 부를 수 있다. 다만 `printEnd`·`printClose` 는 빠져 있다.
- 실행하면 `hello()` 가 `window.open` 으로 합포 분할 페이지를 연다. 서버에서는 끄는 스위치가 필요하다.
- `printGo` 는 준비 때 받은 토큰이 있어야 하고, 토큰은 한 번만 쓴다. 직전에 조건을 다시 본다. 내부 확인창은 문구가 정확히 「송장을 출력하시겠습니까?」일 때만 통과한다. 재출력 문구는 거절한다.
- `pSettings` 는 `#pre_print` 켜짐, 이지에이전트 연결, 프린터 이름 `BIXOLON SLP` 를 요구한다. **서버에도 같은 이름의 프린터가 있어야 지금 안전 점검을 그대로 쓴다.**
- `#pre_print` 를 끄면 `is_print=0` 이라 에이전트로 파일이 가지 않는다. 부여 후 재출력이 안 되므로 **PDF 를 영영 못 받는 막다른 길이다. 쓰지 않는다.**

### 2.4 코드 경로

- 도우미 흐름 제어(`runCommit`·`runPrint`·`printOne`·`watchOne`)는 `ez_split.html` 안에 있고 사람용 `confirm` 이 섞여 있다. 계산은 `ez_split_calc.js` 로 분리돼 있고 Node 에서 불러 쓸 수 있다(`module.exports`).
- `ez_collect.js` 의 폴더 접근은 File System Access 라 **사용자 권한 허락 화면**이 필요하다. 사람 없는 서버에는 맞지 않는다. 다만 `pickFiles`·`logAdd` 등 순수 함수는 Node 에서 그대로 쓸 수 있다.
- `picking_ez.html` 의 `loadFile(file, { collect: true })` 는 묻지 않고 늘 ➕추가 등록한다. `pkAppendMerge` 가 목록·인쇄완료·인쇄이력의 송장번호를 걸러 **「같은 송장 두 번 출력 금지」** 를 지킨다. `meta/jobKey` 로 다른 PC와의 덮어쓰기도 막는다.
- WMS 로그인은 구글(`signInWithRedirect`)뿐이고, 권한은 `superadmins/{uid}`·`userGroup/{uid}` 로 본다.
- 고정 PC에서 도는 전례가 있다: `tools/store_agent`(작업 스케줄러, 이 PC 전용 암호화 키, HMAC 서명으로 Cloud Function 호출, `adctl/storeStatus` 에 상태 남김).

### 2.5 선행 조건 (아직 안 된 것)

도우미 경로의 `commit`·`printGo` 는 실제 성공 기록이 아직 없다(메모 기준 첫 실사용 대기, 10-31 에이전트 로그의 출력 0건). 로그의 376건은 사람이 이지어드민 화면에서 직접 출력한 것이다.

**대표님 크롬에서 도우미로 실제 출력을 먼저 여러 번(5영업일 권장) 성공시켜야 한다. 그 전에 서버로 옮기지 않는다.**

## 3. 전체 구조

```
 대표님 폰·PC ── secretary.html (슈퍼관리자)
                     ⇅  Firebase RTDB  secretary/*
 ┌─ 비서 서버 (윈도우, 사용자 세션 상시 유지) ───────────────────────┐
 │  secretary-core (Node 프로세스 하나)                              │
 │   ├ 스케줄러 ─ 작업 큐 ─ 사이트 잠금                              │
 │   ├ 로그인 비서 : 사이트 어댑터 (ezadmin / ebut)                  │
 │   └ 업무 비서  : 레시피 (ez_daily, 나중에 다른 일)                │
 │        │ Playwright (화면 있는 크롬, 사이트별 프로필)             │
 │        ├ 이지어드민 탭 + ez_helper.js                             │
 │        └ picking_ez.html → PDF 등록                               │
 │  이지에이전트 ⇄ 가상 프린터 → C:\ez_PrintAgent\PdfFile            │
 │  비밀 저장소 (윈도우 DPAPI / 자격 증명 관리자)                    │
 └───────────────────────────────────────────────────────────────────┘
                     ⇅  Firebase  wms_sync/groups/{gid}/picking_ez
 창고 PC ── picking_ez.html 그룹 인쇄만 (지금 화면 그대로)

 Cloud Function : secretaryToken(서버 로그인 토큰), secretaryWatch(5분마다 생존 감시)
```

정해 둔 것:

- **판단은 코드로 한다.** 실행 중에 AI 가 화면을 보고 판단하지 않는다. 송장은 같은 입력에 늘 같은 결과가 나와야 한다.
- **서버는 한 대, 프로세스는 하나.** 작업 스케줄러는 프로세스를 띄우고 죽으면 다시 띄우는 일만 한다.
- **지금 수동 경로를 지우지 않는다.** 서버 장애 때의 대체 수단이다.

## 4. 구성 요소

### 4.1 로그인 비서

사이트마다 어댑터 하나를 둔다.

```
check()  → ok | expired | blocked | unknown     읽기만
login()  → ok | needHuman | failed              비밀 저장소에서 꺼내 입력
```

| | 이지어드민 | 이벗 |
|---|---|---|
| 점검 | 조회 화면이 로그인 창 없이 열리는지 | `/cs/cs200main_jdata` 응답이 HTML(로그아웃)이 아닌지 (이미 도우미에 있는 판별) |
| 계정 | 비서 전용 아이디 권장 | 스타·화물 계정이 달라 **프로필 2개** |

동작 규칙:

- 운영 시간에 10분마다 점검한다. 점검 주기는 V4 결과로 정한다.
- 업무 시작 직전에 한 번 더 점검한다. 실패하면 작업을 시작하지 않는다.
- **재로그인은 사이트당 1회만 시도한다.** 실패하면 `needHuman` 으로 멈추고 보고한다. 반복 시도로 계정이 잠기는 것을 막는다. 대표님이 해제해야 다시 시도한다.
- **캡차·기기 인증·OTP 가 나오면 우회하지 않고 바로 멈춘다.** 대표님이 원격으로 들어가 직접 로그인하면 같은 프로필에서 이어 간다. 인증번호를 Firebase 로 넘기지 않는다.
- 봇 탐지를 숨기는 조작을 하지 않는다.

비밀번호:

- 윈도우 DPAPI 또는 자격 증명 관리자에 그 서버 사용자 전용으로 저장한다(`tools/store_agent` 와 같은 방식).
- 코드·Firebase·git·로그·화면 캡처·Playwright 추적 파일에 남기지 않는다. 로그인 단계는 캡처와 추적을 끈다.
- 입력은 대표님이 서버에서 직접 한다. 채팅·문서로 전달하지 않는다.

### 4.2 WMS 쪽 인증

구글 로그인을 자동화하지 않는다. 구글은 자동화 브라우저 로그인을 막을 수 있고 서버에 구글 비밀번호를 둬야 한다.

- `secretaryToken` 함수: 서버가 HMAC 으로 서명해 요청하면(store_agent 와 같은 틀) uid `secretary-server` 의 커스텀 토큰을 돌려준다.
- 비서 코어와 서버 크롬이 이 토큰으로 로그인한다. `firebase.auth().signInWithCustomToken` 이면 기존 페이지 코드를 거의 안 고친다.
- `userGroup/secretary-server = makechango` 로 등록해 피킹이지 작업과 박스 기록을 읽고 쓴다.
- `secretary/*` 는 슈퍼관리자와 이 uid 만 쓴다. 슈퍼관리자 권한은 주지 않는다.
- 위험: 서버가 뚫리면 그룹 데이터 전체가 노출된다. 그래서 원격 접속을 잠근다(4.7).

### 4.3 스케줄러와 작업 큐

작업 한 건의 상태:

```
queued → running → done
                 ↘ stopped   (점검에 걸려 멈춤, 되돌릴 것 없음)
                 ↘ waiting   (승인 대기)
                 ↘ unknown   (되돌리기 어려운 단계의 결과를 모름 → 잠금)
```

- **사이트당 한 번에 한 작업.** RTDB 트랜잭션으로 `secretary/locks/{site}` 를 잡는다.
- **잠금은 시간이 지나도 저절로 풀리지 않는다.** 서버가 재시작하면 남은 잠금을 보고 작업 기록을 대조한다.
  - 되돌리기 어려운 단계 전이면 그 작업을 `stopped` 로 닫고 잠금을 푼다.
  - 그 단계 중이면 `unknown` 으로 두고 대표님 해제를 기다린다.
- **중복 실행 방지:** 작업 키 = `레시피:날짜:회차` (예: `ez_daily:2026-11-02:오후`). 트랜잭션으로 한 번만 만들어진다. 수동 실행도 같은 키를 쓴다. 다시 하려면 사유를 적고 새 회차를 연다.
- **놓친 일정은 몰아서 하지 않는다.** 정한 시각 + 30분 안에 시작 못 하면 건너뛰고 보고한다.
- **오래된 명령은 버린다.** 5분 넘은 수동 실행 명령은 실행하지 않는다.
- **자정 근처(23:30~00:30)에는 시작하지 않는다.** PDF 날짜 폴더가 바뀌기 때문이다.
- **도우미와의 충돌:** `ez_split.html` 이 잠금을 읽어 비서 작업 중이면 ②·③ 실행 버튼을 막는다.

단계별 재시도 규칙:

| 등급 | 단계 | 자동 재시도 | 결과를 모를 때 |
|---|---|---|---|
| 읽기 | 로그인 점검, `search`, `read`, `printPrep`, `printStatus` | 1회 | 멈춤 |
| 화면만 | `fill`, `reset` | `reset` 후 1회 | 멈춤 |
| **되돌리기 어려움** | `commit`, `printGo` | **절대 안 함** | `unknown` 잠금 |
| 중복 방지 있음 | 피킹이지 등록 | 1회 (`pkAppendMerge` 가 거름) | 멈춤, PDF 보존 |

되돌리기 어려운 단계는 다음 순서를 지킨다.

1. Firebase 에 **의도를 먼저 기록**한다(`intent: { step, supplier, count, hash, at }`).
2. 기록 성공을 확인한다. 실패하면 누르지 않는다.
3. 한 번 누른다.
4. 결과를 기록한다.

재시작했을 때 의도만 있고 결과가 없으면, 자동으로 다시 누르는 경로는 코드에 존재하지 않는다.

### 4.4 업무 비서: 레시피 `ez_daily`

| # | 단계 | 사용하는 것 | 멈추는 경우 |
|---|---|---|---|
| 0 | 사전 점검 | 5.1 표 | 하나라도 어긋남 |
| 1 | 검색·읽기 | `search` | 줄 수 ≠ 이지어드민 전체 수 |
| 2 | 분할 계산 | `Z.buildOrders`, `Z.planExisting`, `boxes` | 확인 필요 있음(5.1) |
| 3 | 화면에 채우기 | `Z.fillPayload`, `fill` | `skipped` 1건 이상 |
| 4 | ★ 일괄합포제외 | `commit { auto, lockUnpack }` | 응답 오류·실패 목록 |
| 5 | 반영 대조 | `search`, `Z.verifyAfter` | `notApplied` 1건 이상 |
| 6 | 공급처별 미리 보기 | `printPrep` | `problems`, 건수 상한 |
| 7 | 승인 또는 자동 통과 | 5.2 | 승인 없음 |
| 8 | ★ 송장 부여 (공급처마다) | `printPrep` → `printGo` → `printStatus` | 건수 변동, `Z.printState` ≠ done |
| 9 | PDF 확인 | `EZC.pickFiles`, 파일 수 대조 | 파일 수·열림 불일치 |
| 10 | 피킹이지 등록 | `picking_ez.html` | `added + dup ≠ 부여 건수` |
| 11 | 보고 | `secretary/jobs` | — |

★ = 되돌리기 어려운 단계. 8단계는 앞 공급처의 `print_end` 뒤에 다음 공급처로 넘어간다(지금 도우미와 같음).

기존 코드 재사용과 필요한 작은 변경:

| 대상 | 방법 | 변경 |
|---|---|---|
| `ez_helper.js` | Playwright `addScriptTag` 후 `page.evaluate(__mkwEzHelper.xxx)` | ① 무인 스위치(`hello` 팝업·상태 상자 끔) ② `printEnd`·`printClose` 공개. 명령 자체는 그대로 |
| `ez_split_calc.js` | Node 에서 그대로 불러옴 | 없음 |
| `ez_collect.js` | 순수 함수만 Node 에서 사용 | 없음 |
| 흐름 제어 | `runCommit`·`runPrint` 흐름을 레시피로 다시 씀 | 사람용 `confirm` 은 승인 규칙(5.2)으로 대체 |
| `picking_ez.html` | `window.PK_AGENT.register(file)` 를 추가 | `pkMergeFiles` + `loadFile({collect:true})` 를 감싸 `{ added, dupList, dupPrinted }` 를 돌려줌 |

도우미 판 고정: 서버가 허용하는 `VER` 목록을 갖는다. `main` 에 도우미가 새로 배포되면 **서버는 멈추고 보고**한다. 낮에 배포한 코드가 그날 송장을 바로 건드리지 않게 하기 위해서다.

대화창 처리: Playwright 의 `dialog` 는 **전부 거절하고 기록**한다. 누르는 확인창은 도우미 안의 정해진 문구 검사만 통과한다. 예상 못 한 창이 뜨면 안전한 쪽으로 멈춘다.

PDF 보관: 등록 성공 뒤 폴더에서 지운다(지금 기본과 같음). 원본은 서버 백업함에 하루 둔다. 등록 실패면 지우지 않는다.

### 4.5 비서 관리 화면 (`main/secretary.html`, 슈퍼관리자)

| 영역 | 내용 |

| 서버 생존 | 🟢 정상 / 🔴 N분째 소식 없음. 서버 이름, 코어·도우미·에이전트 판, 디스크 여유 |

| 조작 | ⏸ 전체 멈춤, ▶ 수동 실행, ✅ 승인, 🔓 잠금 해제(사유 필수) |

나중에 캐릭터 비서를 입힐 수 있게 데이터는 비서(사이트·레시피) 단위로 나눈다. 이번 범위에는 캐릭터를 넣지 않는다. 메뉴는 `wms_pages.js`, 카피라이트는 `/mm_copy.js`.

```

  sites/{site}        { state, checkedAt, lastLoginAt, msg }
  schedules/{id}      { recipe, days, times, enabled, mode, params, caps }
```

생존 감시: 서버가 죽으면 스스로 보고할 수 없다.

- 화면: 3분 넘게 `server.ts` 가 멈추면 🔴
- `secretaryWatch`(Firebase 예약 함수, 5분마다): 일정 시각이 지났는데 작업이 없거나 서버가 멈추면 특이사항에 기록

멈춤: 코어가 `control/pause` 를 실시간으로 듣는다. 단계 사이마다 확인하고 ★ 단계 직전에 다시 확인한다. 이미 진행 중인 `printGo` 는 중간에 끊지 않고 그 공급처 `print_end` 까지 기다린 뒤 멈춘다. 끊으면 부여와 PDF 가 어긋나기 때문이다.

### 4.6 창고 PC

바꾸지 않는다. 그룹 인쇄 화면을 그대로 쓴다. 이지에이전트와 일괄합포제외 절차가 필요 없어진다. 서버 장애 때를 위해 합포 분할 페이지와 도우미 안내는 남긴다.

### 4.7 서버 보안

- 원격 데스크톱 포트를 인터넷에 열지 않는다. 사설망(VPN)이나 2단계 인증이 있는 원격 도구로만 접속한다.
- Firebase 로는 정해진 명령 종류만 받는다. 임의 코드를 실행하는 경로를 만들지 않는다.
- 캡처·추적 파일은 서버 안에 7일만 두고 Firebase 로 올리지 않는다.

## 5. 자동 진행 조건과 멈춤 조건

### 5.1 ★ 단계 전 점검 (전부 만족해야 함)

| 분류 | 조건 |
|---|---|
| 제어 | 전체 멈춤 꺼짐, 일정의 단계가 자동이거나 승인 있음, 승인 값이 지금 값과 같음 |
| 중복 | 이 작업 키가 처음, `unknown` 잠금 없음, 사람이 도우미로 진행 중 아님 |
| 시간 | 정한 시간대 안, 서버 시각 오차 1분 이내 |
| 환경 | 이지에이전트 연결, **허용된 판**(1.1.9). 판이 바뀌면 멈춤 |
| 프린터 | 이름이 `BIXOLON SLP` 하나, **`Get-Printer` 로 본 드라이버·포트가 허용 목록(가상)**. 실제 프린터로 종이가 나가지 않게 이름만 믿지 않는다 |
| 도우미 | 허용된 `VER`, `pSettings`·`pRowProblems` 문제 0건 |
| 대조 | `verifyAfter` 정상 완료, 미리 본 건수 = 출력 직전 건수 |
| 상한 | 5.3 범위 안 |
| 저장 공간 | 디스크 여유 5GB 이상, 오늘 PDF 폴더 쓰기 가능 |
| 분할 | 「확인 필요」 없음. 기간 밖 발주일은 상한 안이면 특이사항으로 알리고 진행 |

### 5.2 단계별 도입

한 단계씩 올리며, 내리는 것은 언제든 한 번에 한다.

| 단계 | 내용 | 다음으로 가는 기준 |
|---|---|---|
| A 점검만 | 1·2·6단계만, 부여 없음. 계산 결과를 대표님 실제 작업과 비교 | 5영업일 동안 계산 일치, 멈춤 이유 모두 설명됨 |
| B 승인 | ★ 전에 멈추고 화면에서 ✅. 승인은 `건수·묶음 해시`에 묶여 값이 바뀌면 무효 | 10영업일 연속 사고 0건 |
| C 자동 | 조건을 모두 통과하면 승인 없이 진행. 공급처·회차별로 켠다 | — |

### 5.3 건수 상한

- 자료: 최근 14일 최대 106묶음. 한 묶음 30장이면 약 3,180건이다(묶음이 다 차지 않을 수 있어 실제 건수는 더 적다).
- 초기값(대표님 확인 전 임시값): **회차 합계 3,500건 이하**, 공급처별 최근 평균의 2배 이하.
- 넘으면 숫자를 보여 주고 멈춘다. 대표님 승인으로만 넘어간다.
- 0건은 실패가 아니라 정상 건너뜀이다.

### 5.4 진행 중 멈춤

아래 어느 하나면 멈추고, ★ 는 다시 누르지 않는다.

- 예상 못 한 대화창, 도우미 끊김, 세션 만료, 화면 구조 변화(버튼을 못 찾음)
- `print_result` ≠ 2, `print_end` 없이 끝남, 10분 무변화
- 부여 수 ≠ `print_result` 합과 PDF 수, 못 여는 PDF
- 등록 후 `added + dup` ≠ 부여 건수, `jobKey` 충돌
- 어제 작업이 남은 피킹이지에 추가될 때는 특이사항으로 알림(추가 자체는 지금 동작과 같다)

## 6. 서버 종류 비교

이지에이전트가 윈도우 프로그램이고 사용자 세션에서 도므로 리눅스 서버는 후보에서 뺀다.

| | 상시 미니 PC (사무실·창고) | 클라우드 윈도우 서버 |
|---|---|---|
| 접속 IP | 지금 쓰는 인터넷과 같아 **제한에 걸릴 위험이 낮음** | 데이터센터 IP → **V5 통과 필요** |
| 비용 (미확인 추정) | 처음에 수십만 원, 이후 전기·인터넷 정도 | 초기 없음, 윈도우 포함 월 사용료. 사양별 실제 금액은 구입 결정 직전 공식 요금표로 확인 |
| 정전·인터넷 장애 | 그 건물과 함께 멈춤. 다만 그 건물에서는 어차피 인쇄·작업도 멈춤. **창고가 여러 곳이면 다른 창고도 영향을 받음** | 건물 장애와 무관 |
| 하드웨어 고장 | 직접 교체, 복구 절차 필요 | 재생성 쉬움 |
| 윈도우 세션 유지 | 자동 로그인 + 잠금으로 쉬움 | 원격 끊김 상태에서도 도는지 V7c 필요 |
| 개인정보 | 사내에 머묾 | 클라우드 저장·처리 추가, 위탁 고지 검토 |
| 시험 쉬움 | **기존 PC로 먼저 시험 가능** | 시험 기간만 빌릴 수 있음 |
| 약관 | 계정 자동화 문제만 | 계정 자동화 + 데이터센터 접속 문제 |

**권장: 미니 PC.** IP 위험이 없고 서버가 멈추는 경우 대부분에서 인쇄도 함께 멈춰 손해가 크게 늘지 않는다. 비용도 오래 쓸수록 유리하다. 사고에 대비해 UPS 와 복구 절차(설치 스크립트로 재설치, 비밀번호 재입력)를 함께 둔다.

클라우드로 바꾸는 경우: 창고가 멀리 나뉘어 건물 장애의 영향이 크거나, 사무실 인터넷이 자주 끊길 때. 대신 V5 와 V6 를 데이터센터 IP 로 통과해야 한다.

**서버를 사기 전에는 기존 PC의 별도 윈도우 사용자로 검증한다.** 스토어 수집기는 DMZOOT 전용 규칙을 그대로 지키며 이번 구조에 넣지 않는다. 고정 IP 가 필요한 그 일은 그 PC에 남는다.

| **V7c** | 무인 동작 | 가상 프린터 후보(ezPDF Builder, 또는 `Generic / Text Only` + `NUL` 포트)마다 저장 창이 뜨는지, 결과 파일이 쌓이는지, 라이선스 확인. 재부팅 후 자동 시작, 원격 끊김·잠금 상태에서 V7a 반복 | 사람 없이 8시간에 30묶음 이상 처리, 창·파일 누적 없음, 재부팅 후 복귀 | 이름 맞춘 NUL 프린터로 전환 |
| **V7d** | 화면 연결 | Playwright 크롬에서 이지어드민 페이지가 `ez_socket` 으로 에이전트에 붙고 `readyState 1`, 프린터 목록 수신. S700 **검색까지만**, 출력 안 누름 | `printPrep` 의 `problems` 가 0건(또는 0건 주문만) | 일반 크롬 프로필로 전환, 안 되면 재설계 |
| **V8** | PDF → 피킹이지 | **시험 그룹**에서 진행. 실제 작업에 섞지 않는다. `secretary-server` 토큰으로 페이지 진입 → 실제 양식을 본뜬 가짜 송장 PDF 등록(개인정보 있는 실제 PDF 는 쓰지 않음) → 같은 파일 재등록 → 다른 PC 화면 확인 → 등록 중 jobKey 변경 유도 | 1회차 `added = N`, 2회차 `added = 0`, 다른 PC에 실시간 표시, 충돌 때 등록 안 되고 보고 | 토큰 진입 실패 시 전용 구글 계정 + 사람 최초 로그인 |
| **V9** | 전체 시험 (별도 승인) | V1~V8 통과 후. 도입 B 단계로 소량 공급처 1회차, 대표님 입회 | 부여 수 = PDF 수 = 등록 수, 재출력 0, 창고 인쇄 정상, 수동 경로로 복귀 가능 | B 단계 유지, 원인 수정 |

참고: `print_start` 의 파일 주소(`data/clf/*.html`)를 에이전트 없이 직접 받는 길도 있다. 페이지와 에이전트 사이를 흉내 내야 해서 이지어드민이 기대하는 동작을 벗어날 수 있으므로 **이번 설계에서 쓰지 않는다.** 이지에이전트 경로가 막힐 때만 약관과 함께 다시 검토한다.

### 서버 도입 판단

| 결과 | 결정 |
|---|---|
| V1·V2·V4·V7·V8 통과 + V3 또는 전용 계정 + V5·V6 문제 없음 | 서버 도입, 구현 계획 작성 |
| 자동 로그인만 막힘, 세션이 하루 이상 유지됨 | 도입 가능. 만료 때 사람이 원격 로그인 |
| 세션이 자주 끊기고 자동 로그인도 막힘 | **서버 보류**, 대표님 크롬 + 도우미 자동화 유지 |
| V6 에서 금지 | 그 사이트 서버 자동화 안 함 |
| V7 실패 | 부여·PDF 는 사람 PC에 남기고 등록까지만 서버 |

## 8. 작업 순서

1. 대표님 결정 (10장)
2. 도우미 실사용 성공 기록 쌓기 (2.5)
3. V6 문의와 V1·V2·V3 로그인 시험
4. V7·V8 시험 (송장 없음)
5. 판단표로 서버 도입 결정, 구입
6. 구현 계획 작성 후 구현 → 도입 A → B → C

## 10. 대표님 결정 사항

순서대로 하나씩 확인한다. 괄호는 답을 받기 전까지 쓰는 권장값이다.

1. 자동 분할 기준은 무엇으로 할까? (「기존대로」 고정, 처음 보는 구성이 있으면 멈춤) 원래 설계서는 그날 주문량·인원에 따라 대표님이 막대를 조절한다고 되어 있어, 이 답이 자동화 범위를 정한다.
2. 최종 목표는 완전 자동인가, 승인 유지인가? (B 승인으로 시작, 공급처별로 C 를 켬)
3. 비서 전용 이지어드민·이벗 아이디를 만들 수 있나? (만듦)
4. 검증을 어느 PC 에서 할까? (실제 프린터 없는 기존 PC의 별도 윈도우 사용자)
5. 서버 종류 (미니 PC)
6. 회차와 시각, 건수 상한 (5.3 임시값)
7. 멈췄을 때 알림 수단 (1차는 화면, 폰 알림은 이후 결정)
8. 이 PC 외 다른 곳의 「BIXOLON」도 가상 프린터인가, 창고 PC 인쇄는 어떤 프린터인가? (서버는 가상, 창고는 실제로 가정)
