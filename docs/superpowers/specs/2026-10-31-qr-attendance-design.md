# QR 출퇴근기록기 설계

> **2026-10-31 변경(범위):** 전체 관리(고객사 관리·여러 회사)는 급여관리 탭 안(iframe)의 슈퍼관리자만. 그 밖에서는 슈퍼관리자도 관리자 QR 주소의 한 회사·기록 탭만 보고, 주소 없이 열면 급여관리로 보낸다. 담당 회사가 여럿인 담당자도 관리자 QR로 들어오면 그 회사만 보인다.
> **2026-10-31 변경:** 보관 기간은 1년(동의서도 1년). 담당자는 관리자 QR·주소로 들어와 기록 보기와 엑셀만 가능하고, 기록 수정·직원·메일·QR은 슈퍼관리자만. 보고서 양식은 일간 근태일지·주간 근태표·월간 근태표로 나뉜다. 슈퍼관리자는 급여관리 탭으로 들어간다. 아래 본문과 다르면 이 줄이 우선한다.

작성일 2026-10-31 · 상태: 대표님 검토 대기

## 목적

어떤 회사든 쓸 수 있는 고객사용 출퇴근 기록 메뉴. 고객사를 등록하면 고객사마다 QR과 근태 기록이 분리되고, 아르바이트·직원은 폰으로 QR만 찍어 출퇴근한다. 담당자는 기록을 조회·수정·엑셀로 받고, 정한 주기로 메일 보고서를 받는다. 내부 급여관리(`payroll.html`) 근태와는 데이터를 공유하지 않고 연동하지 않는다.

## 확정한 결정

| 항목 | 결정 |
|---|---|
| 고객사 담당자 로그인 | 구글 로그인 (등록 메일은 구글 계정이어야 함) |
| 직원 본인 확인 | 문자 인증 없음. 이름·휴대폰번호 + 폰 기억 |
| 위치 제한 | 없음 |
| QR | 인쇄용 고정 QR. 유출 시 재발급 |
| 보관 기간 | 3년 후 자동 삭제 |
| 메일 수단 | Gmail 앱 비밀번호 (nodemailer) |
| 직원 화면의 내 기록 | 이번 달 1일~말일만 표시 |

**안내 문구 원칙:** 직원에게 「기록이 한 달 뒤 삭제된다」고 안내하지 않는다. 실제 보관은 3년이므로 사실과 다르다. 화면에는 「이 화면에는 이번 달 1일부터 말일까지의 기록만 보입니다.」, 동의서에는 3년 보관을 그대로 적는다.

## 구성

| 파일 | 역할 |
|---|---|
| `main/qr_in.html` | QR로 들어오는 폰 화면. 로그인 없음 |
| `main/qr_attend.html` | 관리 화면. 구글 로그인 |
| `functions-qra/index.js` | 서버 함수 입구 |
| `functions-qra/logic.js` | 출퇴근 판단·기간 계산 등 순수 로직 (시험 대상) |
| `functions-qra/mail.js` | 엑셀 생성·메일 발송 |
| `database.rules.json` | `qra` 노드 규칙 |
| `main/wms_pages.js`, `main/wms_login.html`, 메인 메뉴 | 페이지 등록, 담당자 로그인 후 이동, 메뉴 |
| `.github/workflows/firebase-functions-deploy.yml`, `firebase.json` | `qra` 묶음 등록 |

**공개 화면은 DB에 접근하지 않고 서버 함수만 호출한다.** 익명 로그인 + 규칙 방식(반품 링크)은 쓰지 않는다. 규칙만으로 전화번호를 보호하기 어렵기 때문이다.

`qr_in.html` 에는 `wms_access.js` 를 넣지 않는다. 이 스크립트가 싣는 구글 애널리틱스로 QR 열쇠가 든 주소가 나가는 것을 막기 위해서다. `wms_pages.js` 에는 `gate:false`, 「항상 공개」 고정으로 등록한다. `qr_attend.html` 은 `data-floor="1"` 게이트에 더해 자체 인증(담당 고객사 확인)을 한다. 두 페이지 모두 `/mm_copy.js` 를 넣는다.

## 데이터

```
qra/companies/{cid}   { name, site, logo, off, qrKey, adminEmails:{ekey:email},
                        mail:{ freq:'off|daily|weekly|monthly', to:[], cc:[], lastPeriod, lastError }, at, by }
qra/keys/{qrKey}      cid
qra/admins/{ekey}/{cid}  true
qra/workers/{cid}/{wid}  { name, phone, consentAt, consentVer, tokens:{해시:{at}}, lastAt, at }
qra/open/{cid}/{wid}     { logId, month, in, lastAt, lastType }  근무 중 기록과 마지막 동작
qra/tokens/{cid}/{해시}  wid                             폰 토큰으로 직원을 찾는 색인 (함수 전용)
qra/logs/{cid}/{YYYY-MM}/{logId}
                      { wid, name, phone, in, out, inDev, outDev, status, edits:{...} }
qra/mailLog/{cid}/{id}   { at, period, ok, error, to }
```

- `wid` 는 `cid + 휴대폰번호` 의 해시. 같은 회사 안에서 휴대폰번호가 사람을 구분하므로 동명이인도 문제없다.
- 기록은 출근 시각(한국 시간) 기준 달에 넣는다.
- `logo` 는 브라우저에서 긴 변 400px 로 줄여 150KB 이하 데이터로 저장한다. Storage 를 쓰지 않아 규칙이 늘지 않는다.
- `status`: `open`(근무 중) · `done`(완료) · `noout`(퇴근 미기록).

## 권한

| 노드 | 읽기 | 쓰기 |
|---|---|---|
| `companies/{cid}` | 슈퍼관리자, 그 회사 담당자 | 슈퍼관리자. 담당자는 `site`·`logo`·`mail` 만 |
| `admins/{ekey}` | 슈퍼관리자, 그 메일 본인 | 슈퍼관리자 |
| `workers`, `logs`, `open`, `mailLog` | 슈퍼관리자, 그 회사 담당자 (`open` 은 함수 전용) | 서버 함수만 |
| `keys` | 함수 전용 | 서버 함수만 |

`mail.lastPeriod`·`lastError` 는 서버 함수만 쓴다. 담당자 판별 규칙은 `vendorByEmail` 과 같은 메일 키(`toLowerCase().replace('.',',')`)를 쓰고 `auth.token.email_verified` 를 함께 확인한다.

| `qraExport` | 담당자·슈퍼관리자 | 선택 기간 엑셀 생성. 메일과 같은 양식 |
| `qraSendNow` | 담당자·슈퍼관리자 | 선택 기간 메일 즉시 발송 (시험·재발송) |

고객사 등록 자체는 슈퍼관리자가 관리 화면에서 `companies`·`keys`·`admins` 를 한 번에 쓴다. 공개 함수는 인스턴스별 IP당 분당 30회로 제한한다.

## 폰 화면 흐름

첫 화면에 로고·회사명·현장명·현재 시각·버튼을 두고, 그 아래에 이번 달 내 기록과 이용 순서 3단계를 놓는다. 어두운 바탕에 금색 포인트의 고급스러운 시안을 따른다.

1. **처음:** 이름·휴대폰번호 입력 → 동의 체크 → 출근하기. 서버 시간으로 기록하고 폰 토큰을 저장한다.
2. **같은 폰 재방문:** 이름이 미리 채워져 있고 동의 없이 버튼만 누른다.
3. **폰 변경:** 이름과 번호가 등록과 맞으면 동의를 생략하고 토큰을 새로 발급한다.
4. **번호는 같은데 이름이 다름:** 기록을 막고 담당자 문의를 안내한다. 등록된 이름은 보여 주지 않는다.
5. **출근만 찍힌 상태:** 퇴근하기 버튼. 누르면 퇴근 처리.

폰 토큰은 32바이트 난수이며 서버에는 해시만 둔다. 폰 저장소가 막힌 브라우저는 매번 이름·번호를 입력한다. 대리 출근 표시용으로 폰별 식별값을 별도로 저장해 기록한다.

### 출퇴근 판단 규칙 (`logic.js`)

- 열린 기록 없음 → 출근 가능.
- 열린 기록이 18시간 미만 → 퇴근 가능. 자정을 넘겨도 정상.
- 열린 기록이 18시간 이상 → `noout` 으로 닫고 출근 가능.
- 직전 기록 후 60초 안의 같은 요청 → 새로 쓰지 않고 직전 결과 반환.
- 화면 상태와 서버 상태가 다른 요청 → 쓰지 않고 현재 상태를 돌려줘 화면을 갱신.
- 동시 요청은 `open/{cid}/{wid}` 트랜잭션으로 한 건만 처리.

## 관리 화면

- **고객사 (슈퍼관리자):** 등록·중지. 회사명, 현장명, 로고, 담당자 구글 메일 여러 개.
- **QR:** A4 안내문 인쇄(로고·회사명·QR·이용 순서), QR 이미지 저장, 재발급.
- **기록:** 기간·이름 검색, 근무시간 표시, 수정·수기 추가, 엑셀 다운로드. 같은 날 한 폰에 여러 이름이면 표시.
- **직원:** 목록, 이름 수정, 삭제.
- **메일:** 주기, 받는 사람·참조 여러 명, 지금 보내기, 발송 기록과 실패 표시.

담당 고객사가 하나면 바로 그 화면으로, 여럿이면 고객사를 고른다. `wms_login.html` 은 그룹에 없는 사용자가 `qra/admins` 에 있으면 `qr_attend.html` 로 보낸다.

근무시간은 퇴근에서 출근을 뺀 값이며 휴게시간은 빼지 않는다.

## 동의서 (`consentVer` 1)

> **개인정보 수집·이용 동의**
> - 수집하는 곳: {고객사명}
> - 항목: 이름, 휴대폰번호, 출퇴근 시각, 접속 기기 식별값
> - 목적: 출퇴근 기록과 근태·급여 관리
> - 보관 기간: 수집일부터 3년, 이후 파기
> - 처리 위탁: 기록 시스템의 운영은 메이크마인이 맡습니다.
> - 동의하지 않으실 수 있으나, 이 경우 QR 출퇴근 기록을 이용할 수 없습니다. 담당자에게 다른 기록 방법을 문의해 주세요.

법률 검토를 받은 문구가 아니다. 실제 고객사 제공 전 노무사·변호사 확인을 권장한다. 문구를 바꿔 `consentVer` 를 올리면 다음 방문 때 다시 동의받는다.

## 자동 메일

| 주기 | 발송 시각 | 대상 기간 |
|---|---|---|
| 매일 | 매일 7시 | 전날 |
| 매주 | 월요일 7시 | 지난주 월~일 |
| 말일 | 다음 달 1일 7시 | 지난달 전체 |

- 받는 사람·참조 여러 명. 제목과 본문에 로고·회사명을 넣는다.
- 본문: 출근 인원, 총 근무시간, 퇴근 미기록 건수.
- 첨부 엑셀: `근태일지`(날짜, 이름, 휴대폰, 출근, 퇴근, 근무시간, 비고), `사람별 합계`. 기록이 없으면 첨부 없이 「기록 없음」으로 보낸다.
- `lastPeriod` 와 대상 기간이 다르면 보낸다. 실패하면 같은 날 다음 정각(10시까지)에 다시 시도하고, 끝내 실패하면 관리 화면에 표시한다. 놓친 기간은 지금 보내기로 보낸다.
- 비밀값 `GMAIL_USER`, `GMAIL_APP_PASSWORD` 는 대표님이 터미널에서 직접 입력한다. 일반 Gmail 한도는 하루 약 500통이다.

## 보관·삭제

`qraMailTick` 이 하루 한 번 36개월 지난 달의 `logs` 와 `mailLog`, 마지막 기록이 3년 지난 `workers` 를 삭제한다.

## 알고 가는 한계

- 다른 사람의 이름과 번호를 알면 그 사람으로 출근을 찍거나 이번 달 출퇴근 시각을 볼 수 있다. 문자 인증을 빼기로 한 결정의 결과이며, 한 폰 여러 이름 표시로 일부만 잡아낸다.
- QR 사진을 공유하면 어디서든 찍을 수 있다. 위치 제한을 넣지 않기로 했다.
- 공개 함수 호출 제한은 인스턴스별이라 완전한 차단이 아니다.

## 시험

- `logic.js`: `node:test` 로 판단 규칙 전부, 기간 계산(월말·연말·주 경계·한국 시간), 번호 정리.
- 규칙: 배포 후 비로그인·타 계정 읽기 거부를 실제 REST 요청으로 확인.
- 전체: 시험용 고객사로 등록 → QR → 폰 화면 출근·퇴근 → 재방문 동의 생략 → 분리 조회·엑셀 → 메일 실제 수신. 끝나면 시험 데이터 삭제.
