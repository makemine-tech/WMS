# 비서 1단계: 대표님 PC에서 도는 일정 비서 — 설계서·검증 계획

- 작성일: 2026-10-31
- 상태: **초안, 대표님 결정 대기.** 구현·실제 송장 부여는 하지 않았다.
- 범위 근거 (대표님 말씀): 「서버는 1단계 진행시니 항시는 필요없을거야 일단 내 컴퓨터가 거의 항시로 켜있고 하니 거기 세팅하면되고」
- 뒤로 미룬 것: [비서 서버 설계서](2026-10-31-secretary-server-design.md)의 서버 종류 비교, 서버 IP 제한, 프린터 없는 서버 시험, 서버 비밀 저장소.

## 1. 목적

서버 없이, **대표님 크롬의 로그인 그대로** 지금 도우미가 일정에 따라 스스로 일한다.

1. 정해진 시각에 사람이 북마크를 누르지 않아도 도우미가 뜬다.
2. 합포제외 → 송장 부여 → PDF → 피킹이지 등록을 순서대로 진행한다.
3. 로그인이 끊기거나 애매하면 멈추고 알린다.
4. 대표님은 비서 관리 화면에서 일정·상태·결과를 보고 멈추거나 수동 실행한다.
5. 창고 PC는 그룹 인쇄만 한다.

성공 기준:

- 잘못 부여된 송장, 두 번 등록·출력된 송장 0건.
- 사람 클릭 없이 시작해서 끝까지 가거나, 어디서 왜 멈췄는지 화면에 남는다.
- PC 나 크롬이 꺼져 일정을 놓치면 나중에 몰아서 하지 않고 놓쳤다고 보고한다.

## 2. 이 PC에서 확인한 사실

- PC 이름 **TOOZ-GRAM**. 스토어 수집기 설치·실행 금지 대상이다. **이번 설계는 수집기를 건드리지 않는다.** 수집기는 DMZOOT 그대로다. 이 PC에 수집기 예약 작업은 없다.
- **절전이 전원 연결·배터리 모두 20분(0x4b0 = 1,200초)으로 설정돼 있다.** 지금 설정대로면 손을 놓은 지 20분 뒤 PC 가 잠들어 일정이 돌지 않는다. 일을 시작하기 전에 고쳐야 할 가장 큰 항목이다.
- 부팅 시각은 오늘 03:27 이다. 재부팅·업데이트로 크롬이 닫힐 수 있다고 봐야 한다.
- 이지에이전트 1.1.9 가 이 PC에서 돌고, 「BIXOLON SLP-D 420」은 가상 PDF 프린터다. 10월 17~31일에 376묶음이 정상 처리됐다. 따라서 **PDF 생성 경로는 이 PC에서 이미 검증된 상태**다. 단, 같은 PC에 실제 프린터(삼성·Xprinter)가 있으니 프린터 점검을 유지한다.
- 크롬 156. 크롬 136부터 기본 프로필에는 원격 디버깅 포트가 막혀, **Playwright 로 대표님 프로필을 조종하는 방식은 쓰지 않는다.**
- 지금 막는 것 세 가지:
  - 사람 클릭 없는 `window.open` 은 팝업으로 막힌다.
  - 도우미는 북마크를 눌러야 뜬다.
  - 자동수집 폴더 권한은 크롬이 사람 허락을 요구할 수 있다.

### 선행 조건

도우미 경로의 `commit`·`printGo` 는 실제 성공 기록이 아직 없다. **대표님이 지금 화면에서 실제 출력을 5영업일 정도 성공시킨 뒤에 무인 실행으로 넘어간다.**

## 3. 전체 구조

```
 Windows 시작 → 크롬 → 확장 「메이크창고 비서」
                        ├ 1분마다: 비서 본부 탭이 있는지 확인, 없으면 열기
                        └ 비서 탭의 이지어드민에 도우미 자동 주입

 크롬 (대표님 프로필, 대표님 로그인 그대로)
   ├ 비서 본부 탭  makewon.com/secretary.html?run=1
   │    일정 → 작업 큐 → 레시피 (ez_job.js + ez_split_calc.js)
   │    ⇅ postMessage
   ├ 이지어드민 탭 (mkw_ez_tab) ez_helper.js ⇄ 이지에이전트 → PdfFile
   └ 피킹이지 탭  picking_ez.html?step=2&agent=1 → PDF 등록
          ⇅ Firebase
 secretary/*  ← 관리 화면 (폰·PC에서 secretary.html 보기만)
              ← secretaryWatch (5분마다 PC 생존 감시, 서버 함수)
 picking_ez/job → 창고 PC 그룹 인쇄 (변경 없음)
```

정해 둔 것:

- **판단은 코드로 한다.** 화면을 AI 가 보고 판단하지 않는다.
- **비밀번호를 저장하지 않는다.** 코드·Firebase·git·확장 어디에도 두지 않는다.
- **WMS 로그인도 대표님 구글 로그인 그대로.** 커스텀 토큰과 전용 계정은 1단계에 필요 없다.
- **봇 탐지를 피하려는 조작은 넣지 않는다.** 캡차·추가 인증이 나오면 멈춘다.
- **지금 수동 경로는 그대로 둔다.** 확장이나 본부가 꺼져 있어도 북마크로 일할 수 있다.

## 4. 구성 요소

### 4.1 도우미 자동 시작: 작은 크롬 확장

후보 비교:

| 방법 | 판단 |
|---|---|
| **직접 만든 확장 (개발자 모드로 설치)** | **채택.** 코드 약 40줄, 외부 도구 없음, 대표님 로그인 그대로 |
| Tampermonkey 사용자 스크립트 | 주입은 되지만 탭 감시·재시작이 약하고 외부 프로그램에 의존 |
| Playwright + 디버깅 포트 | 크롬 136부터 기본 프로필 불가, 포트 노출 위험 |
| 별도 로그인 프로필 | 대표님 로그인과 이중 로그인이 되어 1단계 취지와 다름 |

확장이 하는 일은 딱 두 가지다.

1. **본부 탭 유지:** 크롬 시작 때와 1분마다(`chrome.alarms`) `secretary.html?run=1` 탭을 확인하고 없으면 연다.
2. **도우미 주입:** `*.ezadmin.co.kr` 페이지에서 `window.name === 'mkw_ez_tab'` 이고 opener 가 있을 때만 `ez_helper.js` 를 넣는다. **대표님이 직접 연 이지어드민 탭에는 넣지 않는다.**

이벗도 같은 방식으로 확장한다(`mkw_ebut_tab`). 다만 1단계 업무 레시피는 이지어드민만 만들고, 이벗은 로그인 점검까지만 한다.

필요한 설정(대표님 PC에서 1회):

- `makewon.com` 팝업 허용 → 본부가 클릭 없이 이지어드민·피킹이지 탭을 열 수 있음
- `makewon.com`·이지어드민을 메모리 절약 제외 목록에 추가 → 탭이 잠들지 않음
- 크롬 자동 시작, 절전 끄기 또는 연장(5.3)

### 4.2 비서 본부와 작업 큐

한 페이지가 두 역할을 한다.

- `secretary.html` → 관리 화면 (폰·PC 어디서나, 실행 안 함)
- `secretary.html?run=1` → 실행기 (이 PC에서만)

한 PC, 한 탭만 실행하게 **이중으로** 막는다.

- 탭 중복: `navigator.locks` 로 같은 브라우저의 두 번째 탭은 실행 안 함
- PC 중복: `secretary/runner` 를 트랜잭션으로 잡음. 등록된 PC(이 브라우저에 저장한 runnerId)만 실행. 다른 PC에서 `?run=1` 을 열면 「등록된 실행 PC 아님」으로 멈춤

작업 규칙은 서버 설계서 4.3과 같다.

- 사이트당 한 번에 한 작업, 잠금은 시간이 지나도 저절로 풀리지 않음
- 작업 키 `레시피:날짜:회차`, 트랜잭션으로 한 번만 생성
- **놓친 일정은 몰아서 하지 않음.** 정한 시각 + 30분 안에 시작 못 하면 건너뛰고 보고
- 오래된 명령 무시(5분), 23:30~00:30 시작 금지(PDF 날짜 폴더)
- 재시도: 읽기 1회, 화면 채우기는 `reset` 뒤 1회, **`commit`·`printGo` 절대 안 함**, 등록은 1회(`pkAppendMerge` 가 중복 차단)
- ★ 단계는 의도를 먼저 Firebase 에 기록하고, 기록 성공 뒤 한 번 누르고, 결과를 기록. 크롬·PC 가 중간에 꺼져 의도만 남아 있으면 **`unknown` 잠금, 대표님 해제 전까지 그 사이트 작업 금지**

**대표님과의 충돌:** 같은 크롬을 대표님도 쓴다.

- `ez_split.html` 은 잠금을 읽어 비서 작업 중이면 ②·③ 버튼을 막는다.
- 반대로 대표님이 페이지에서 작업 중이면(`ezHelperState` 또는 잠금) 비서는 시작하지 않고 보고한다.
- 비서 탭 맨 위에 「비서 작업 중 — 탭을 닫거나 이지어드민에서 로그아웃하지 마세요」 표시.
- 진행 중 탭을 닫으면 `beforeunload` 경고가 뜬다(지금 도우미에 이미 있음). 그래도 닫히면 `unknown` 처리.
- 작업 탭은 비서 전용 창에 모아, 대표님의 평소 탭과 섞이지 않게 한다.

**도우미 판 고정:** 본부는 허용된 `VER` 만 실행한다. 도우미가 새로 배포되면 무인 실행을 멈추고 보고한다. 낮 배포가 그날 송장을 바로 건드리지 않게 하기 위해서다.

### 4.4 작업 속도: 사람보다 빠르지 않게

`pace.js` 로 모든 사이트 요청을 한 줄로 세워 간격을 지킨다.

| 동작 | 최소 간격 (임시값, P7 실측으로 조정) |
|---|---|
| 검색·조회 | 앞 요청이 끝난 뒤 5초 |
| 화면 채우기 | 묶음당 3초 (346묶음이면 약 17분) |
| 페이지 이동·창틀 열기 | 3초 |
| 로그인 점검 | 10분 |
| 송장 부여 진행 확인 | 2초 (화면 안의 값만 읽어 서버 요청 없음) |
| 동시 요청 | 사이트당 항상 1개 |

- 사이트가 오류·지연으로 답하면 재촉하지 않고 멈춘다.
- **탐지를 피하려는 것이 아니다.** 사이트에 부담을 주지 않으려는 것이므로 무작위 흉내는 넣지 않고 정해진 간격만 쓴다.
- 지금 `fill` 은 묶음을 쉬지 않고 처리한다. 레시피는 한 번에 한 묶음만 보내 간격을 둔다.

### 4.5 로그인 만료

1단계 기본은 **알림**이다.

- 업무 직전과 운영 시간 10분마다 비서 탭에서 읽기로 점검한다. 이지어드민은 로그인 창 표시 여부, 이벗은 조회 응답이 HTML 인지 본다.
- 끊기면 그 사이트 작업을 시작하지 않고 관리 화면 🔑 + 크롬 알림(9장 4번 결정에 따라 폰 알림 추가).
- 대표님이 평소처럼 로그인하면 다음 점검에서 자동으로 🟢.

자동 재로그인은 **선택 사항**이고 P3 를 통과해야 켠다.

- 크롬 비밀번호 저장이 칸을 채운 경우에만, 확장이 로그인 버튼을 **한 번** 누른다. 비밀번호를 읽거나 저장하지 않는다.
- 크롬은 사람 동작 전에는 채운 비밀번호를 페이지에 넘기지 않을 수 있어 안 될 가능성이 있다.
- 실패, 캡차, 기기 인증, OTP 가 하나라도 나오면 멈추고 알린다. 다시 시도하지 않는다.

### 4.6 비서 관리 화면 (`secretary.html`, 슈퍼관리자)

| 영역 | 내용 |
|---|---|
| PC 생존 | 🟢 TOOZ-GRAM 켜짐 / 🔴 N분째 소식 없음 |
| 준비 상태 | 크롬·확장·본부·도우미 판·이지에이전트·프린터·폴더 권한 |
| 사이트 | 이지어드민·이벗 로그인 상태 |
| 일정 | 요일·시각·회차, 켜기/끄기, 단계(점검만/승인/자동) |
| 오늘 작업 | 단계별 진행, 공급처별 건수 |
| 특이사항 | **맨 위 고정.** 멈춘 이유, 놓친 일정, 해야 할 일 |
| 조작 | ⏸ 전체 멈춤, ▶ 수동 실행, ✅ 승인, 🔓 잠금 해제(사유 필수) |

```
secretary/
  runner               { id, host, ts, ver, helperVer, agentVer, ready:{...} }
  sites/{site}         { state, checkedAt, msg }
  schedules/{id}       { recipe, days, times, enabled, mode, caps }
  jobs/{jobKey}        { state, trigger, by, at, steps, counts, intent, notes }
  locks/{site}         { jobKey, runnerId, at }
  control              { pause, by, at, why }
  commands/{id}        { type, jobKey, by, at, status }
  approvals/{jobKey}   { hash, count, by, at }
```

- 수령자 이름·주소·전화번호는 올리지 않는다.
- 폰에서 ✅ 승인이나 ⏸ 멈춤을 누르면 Firebase 로 본부 탭에 실시간 전달된다.
- `secretaryWatch` 는 본부 탭이 꺼져도 돈다. 일정 시각이 지났는데 작업이 없거나 `runner.ts` 가 멈추면 특이사항에 기록한다.

## 5. 자동 진행 조건과 멈춤 조건

### 5.1 ★ 전 점검

전부 만족해야 한다. 서버 설계서 5.1 표에 다음을 더한다.

- 본부가 등록된 PC, 런너 잠금 소유
- 이 PC 전원 연결 중(`navigator.getBattery`, 지원될 때). 배터리면 멈춤
- 대표님 수동 작업 진행 중 아님
- 프린터 점검: 도우미의 이름 검사(`BIXOLON SLP`)를 쓴다. 웹 페이지는 드라이버를 볼 수 없으므로, 실제 프린터 이름이 그대로 `BIXOLON` 으로 바뀌는 일이 없게 **대표님이 관리**한다. 이 차이는 서버 단계에서 `Get-Printer` 로 메운다

### 5.2 단계별 도입

| 단계 | 내용 | 다음으로 가는 기준 |
|---|---|---|
| A 점검만 | 읽기·계산·미리 보기까지, 부여 없음. 대표님 실제 작업과 비교 | 5영업일 일치, 멈춤 이유 모두 설명됨 |
| B 승인 | ★ 앞에서 멈추고 ✅. 건수·해시가 바뀌면 승인 무효 | 10영업일 연속 사고 0건 |
| C 자동 | 조건 통과 시 진행, 공급처·회차별로 켬 | — |

### 5.3 PC 가 꺼지거나 잠들 때

- 일정 시간대에는 절전하지 않게 한다. **대표님이 전원 설정을 바꾸는 항목**이고, 시험 뒤 적용한다.
- 절전에서 깨면 본부가 시간 차이를 보고 놓친 일정을 건너뛴 뒤 보고한다.
- 노트북 뚜껑을 닫아도 잠들 수 있다. 일정 시간대에는 전원을 연결하고 열어 둔다.
- 건수 상한: 회차 합계 3,500건 임시값(서버 설계서 5.3 근거).

### 5.4 진행 중 멈춤

서버 설계서 5.4 전부 + 탭 닫힘, 크롬 재시작, 절전 복귀, 폴더 권한 잃음.

## 7. 작업 순서

1. 대표님 결정 (9장)
2. P0 기록 쌓기, 약관 확인
3. 확장·본부 뼈대 구현 → P1·P2·P4·P5
4. 관리 화면 + A 단계 (송장 없음) → P3·P7·P8
5. 피킹이지 연결 → P6

## 8. 서버로 옮길 때

다음 중 하나가 생기면 서버 설계서를 다시 꺼낸다.

- 절전·재부팅·대표님 사용과 부딪혀 일정을 자주 놓침
- 이 PC 없이 대표님이 외부에 오래 나가 있어야 함
- 비서 업무가 늘어 탭과 대표님 작업이 자주 부딪힘

이 설계의 `ez_job.js`·`pace.js`·`secretary/*`·관리 화면은 서버에서도 그대로 쓴다. 바뀌는 것은 시작 방식(확장 → Playwright)과 로그인(대표님 → 전용 계정)이다.

## 9. 대표님 결정 사항

순서대로 하나씩 확인한다. 괄호는 답을 받기 전까지 쓰는 권장값이다.

1. 자동 분할 기준 (「기존대로」 고정, 처음 보는 구성이 있으면 멈춤)
2. 최종 목표: 완전 자동인가, 승인 유지인가 (B 승인으로 시작, 공급처별로 C)
3. 회차·시각과 건수 상한 (시각은 대표님 지정, 상한 3,500건)
4. 멈췄을 때 알림 수단 (1차 화면 + 크롬 알림, 폰은 이후 결정)
5. 일정 시간대 이 PC 절전 해제 괜찮은가 (일정 시간대만 해제)
