# 메이크창고 전담비서 1단계: 상시 컴퓨터의 헤드비서와 폰 시동 — 설계서·검증 계획

- 작성일: 2026-10-31
- 상태: **초안, 작업 보류 중.** 대표님이 시간 날 때 이어 간다. 이어 갈 곳은 11장. 구현·실제 송장 부여는 하지 않았다.
- 범위 근거 (대표님 말씀): 「서버는 1단계 진행시니 항시는 필요없을거야 일단 내 컴퓨터가 거의 항시로 켜있고 하니 거기 세팅하면되고」
- 구상 보고서: [메이크창고 전담비서 구상 보고서](https://claude.ai/artifact/RCkuLHHex2fZRoj46yUjZQ)
- 뒤로 미룬 것: [비서 서버 설계서](2026-10-31-secretary-server-design.md)의 서버 종류 비교, 서버 IP 제한, 프린터 없는 서버 시험, 서버 비밀 저장소.

## 1. 목적

**최종 목적: 어느 작업자든 자기 해당 송장만 인쇄해 바로 일한다.**

1단계는 그 앞까지를 만든다. 대표님이 출근해서든 외부에서든 폰으로 「메이크창고 전담비서」 페이지를 열고 자동차 키처럼 시동을 걸면, 상시 컴퓨터가 켜져 있는 한 클릭 한 번으로 이지어드민 흐름이 피킹이지 4단계(그룹 인쇄) 직전까지 준비된다.

1. 시동 또는 정해진 일정으로 시작한다. 사람이 북마크를 누르지 않는다.
2. 상시 컴퓨터의 헤드비서가 사이트 로그인을 챙기고 업무 비서를 깨운다.
3. 이지어드민 비서가 합포제외 → 송장 부여 → PDF → 피킹이지 등록을 순서대로 진행한다.
4. 폰에 건수와 특이사항을 보고한다. 로그인이 끊기거나 애매하면 멈추고 알린다.
5. **인쇄는 작업자가 누른다.** 비서는 종이를 뽑지 않는다.
6. 비서는 업무별로 계속 늘린다. 새 비서는 같은 틀에 레시피만 넣는다.

| 비유 | 실제 |
|---|---|
| 자동차 키 | 전담비서 페이지 (폰·PC) |
| 차 | 상시 컴퓨터 |
| 운전 책임자 | 헤드비서 |
| 엔진 | 업무 비서들 |

성공 기준:

- 잘못 부여된 송장, 두 번 등록·출력된 송장 0건.
- 외부 폰에서 시동 한 번으로 시작해 인쇄 준비까지 가거나, 어디서 왜 멈췄는지 폰에 보인다.
- 상시 컴퓨터가 꺼져 있으면 시동 전에 폰에서 바로 안다.
- PC 나 크롬이 꺼져 일정을 놓치면 나중에 몰아서 하지 않고 놓쳤다고 보고한다.

## 2. 이 PC에서 확인한 사실

- PC 이름 **TOOZ-GRAM**. 스토어 수집기 설치·실행 금지 대상이다. **이번 설계는 수집기를 건드리지 않는다.** 수집기는 DMZOOT 그대로다. 이 PC에 수집기 예약 작업은 없다.
- **절전이 전원 연결·배터리 모두 20분(0x4b0 = 1,200초)으로 설정돼 있다.** 지금 설정대로면 손을 놓은 지 20분 뒤 PC 가 잠들어 일정이 돌지 않는다. 일을 시작하기 전에 고쳐야 할 가장 큰 항목이다.
- 부팅 시각은 오늘 03:27 이다. 재부팅·업데이트로 크롬이 닫힐 수 있다고 봐야 한다.
- 이지에이전트 1.1.9 가 이 PC에서 돌고, 「BIXOLON SLP-D 420」은 가상 PDF 프린터다. 10월 17~31일에 376묶음이 정상 처리됐다. 따라서 **PDF 생성 경로는 이 PC에서 이미 검증된 상태**다. 단, 같은 PC에 실제 프린터(삼성·Xprinter)가 있으니 프린터 점검을 유지한다.
- 크롬 156. 크롬 136부터 기본 프로필에는 원격 디버깅 포트가 막혀, **Playwright 로 대표님 프로필을 조종하는 방식은 쓰지 않는다.**
- 지금 막는 것 세 가지:
  - 사람 클릭 없는 `window.open` 은 팝업으로 막힌다.
  - 도우미는 북마크를 눌러야 뜬다.
  - 자동수집 폴더 권한은 크롬이 사람 허락을 요구할 수 있다.

### 선행 조건

도우미 경로의 `commit`·`printGo` 는 실제 성공 기록이 아직 없다. **대표님이 지금 화면에서 실제 출력을 5영업일 정도 성공시킨 뒤에 무인 실행으로 넘어간다.**

## 3. 전체 구조

```
 대표님 폰·PC ── 전담비서 페이지 secretary.html ── [시동] [멈춤] [승인]  ← 건수·특이사항 보고
                     ⇅ Firebase secretary/*  (외부 어디서든)
 ┌─ 상시 컴퓨터 ──────────────────────────────────────────────────┐
 │ 크롬 지킴이 (작업 스케줄러, 5분마다): 크롬이 꺼져 있으면 다시 켬 │
 │                                                                  │
 │ 크롬 (대표님 프로필, 대표님 로그인 그대로)                       │
 │   확장 「메이크창고 비서」: 헤드비서 탭 유지, 비서 탭에 도우미 주입│
 │   ├ 헤드비서 탭  secretary.html?run=1                            │
 │   │    명령·일정 수신 → 로그인 점검 → 작업 큐 → 비서 깨우기      │
 │   │    ⇅ postMessage                                             │
 │   ├ 이지어드민 비서: 탭 mkw_ez_tab, ez_helper.js ⇄ 이지에이전트  │
 │   ├ 피킹이지 탭  picking_ez.html?step=2&agent=1 → PDF 등록       │
 │   └ (다음 비서: 이벗 반품 …)                                     │
 └──────────────────────────────────────────────────────────────────┘
 secretaryWatch (서버 함수, 5분마다): 상시 컴퓨터 생존·놓친 일정 기록
                     ⇅ Firebase picking_ez/job
 작업자 PC ── picking_ez.html 그룹 인쇄: 인쇄는 작업자가 누름
```

**원격 접속은 비상용이다.** 화면을 원격으로 클릭하는 방식은 깨지기 쉬워 일상 실행 경로로 쓰지 않는다. 일상 명령은 전부 Firebase 로 헤드비서에게 전달된다. 원격 접속은 로그인 풀림·추가 인증·`unknown` 잠금처럼 사람이 그 PC 화면을 봐야 할 때만 쓴다. 2단계 인증이 있는 원격 도구를 대표님이 설치하고, 원격 포트를 인터넷에 직접 열지 않는다.

정해 둔 것:

- **판단은 코드로 한다.** 화면을 AI 가 보고 판단하지 않는다.
- **비서는 인쇄 함수를 부르지 않는다.** 레시피는 피킹이지 등록과 보고에서 끝난다.
- **비밀번호를 저장하지 않는다.** 코드·Firebase·git·확장 어디에도 두지 않는다.
- **WMS 로그인도 대표님 구글 로그인 그대로.** 커스텀 토큰과 전용 계정은 1단계에 필요 없다.
- **봇 탐지를 피하려는 조작은 넣지 않는다.** 캡차·추가 인증이 나오면 멈춘다.
- **지금 수동 경로는 그대로 둔다.** 확장이나 헤드비서가 꺼져 있어도 북마크로 일할 수 있다.

## 4. 구성 요소

### 4.1 도우미 자동 시작: 작은 크롬 확장

후보 비교:

| 방법 | 판단 |
|---|---|
| **직접 만든 확장 (개발자 모드로 설치)** | **채택.** 코드 약 40줄, 외부 도구 없음, 대표님 로그인 그대로 |
| Tampermonkey 사용자 스크립트 | 주입은 되지만 탭 감시·재시작이 약하고 외부 프로그램에 의존 |
| Playwright + 디버깅 포트 | 크롬 136부터 기본 프로필 불가, 포트 노출 위험 |
| 별도 로그인 프로필 | 대표님 로그인과 이중 로그인이 되어 1단계 취지와 다름 |

확장이 하는 일은 딱 두 가지다.

1. **헤드비서 탭 유지:** 크롬 시작 때와 1분마다(`chrome.alarms`) `secretary.html?run=1` 탭을 확인하고 없으면 연다.
2. **도우미 주입:** `*.ezadmin.co.kr` 페이지에서 `window.name === 'mkw_ez_tab'` 이고 opener 가 있을 때만 `ez_helper.js` 를 넣는다. **대표님이 직접 연 이지어드민 탭에는 넣지 않는다.**

이벗도 같은 방식으로 확장한다(`mkw_ebut_tab`). 다만 1단계 업무 레시피는 이지어드민만 만들고, 이벗은 로그인 점검까지만 한다.

필요한 설정(대표님 PC에서 1회):

- `makewon.com` 팝업 허용 → 헤드비서가 클릭 없이 이지어드민·피킹이지 탭을 열 수 있음
- `makewon.com`·이지어드민을 메모리 절약 제외 목록에 추가 → 탭이 잠들지 않음
- 크롬 자동 시작, 절전 끄기 또는 연장(5.3)

### 4.2 헤드비서와 작업 큐

헤드비서는 상시 컴퓨터에 상주하며 두 층으로 나뉜다.

| 층 | 만드는 것 | 하는 일 |
|---|---|---|
| 크롬 지킴이 | 작업 스케줄러 + 짧은 PowerShell (`tools/secretary_ext/`, 창 숨김은 `store_agent` 의 `run_hidden.vbs` 방식) | 5분마다 크롬이 없으면 켠다. Firebase·비밀번호·사이트와 무관. 크롬이 꺼진 뒤의 시동도 이것으로 살아남 |
| 헤드비서 탭 | `secretary.html?run=1` | 명령·일정 수신, 로그인 점검, 작업 큐, 비서 깨우기, 생존 신호(1분마다 `runner.ts`), 보고 |

비서 등록표: 비서 하나는 `{ id, 이름, 사이트, 레시피, 기본 단계, 기본 기간 }` 한 줄과 레시피 파일 하나다. 헤드비서·잠금·보고·시동 화면은 공통이므로 **새 비서는 레시피만 추가**한다. 1단계에 등록하는 비서는 이지어드민 비서 하나이고, 이벗은 로그인 점검만 한다. 다음 후보는 이벗 반품 비서다.

한 페이지가 두 역할을 한다.

- `secretary.html` → 전담비서 페이지 (폰·PC 어디서나, 시동·멈춤·승인 명령만 보냄)
- `secretary.html?run=1` → 헤드비서 (상시 컴퓨터에서만)

한 PC, 한 탭만 실행하게 **이중으로** 막는다.

- 탭 중복: `navigator.locks` 로 같은 브라우저의 두 번째 탭은 실행 안 함
- PC 중복: `secretary/runner` 를 트랜잭션으로 잡음. 등록된 PC(이 브라우저에 저장한 runnerId)만 실행. 다른 PC에서 `?run=1` 을 열면 「등록된 실행 PC 아님」으로 멈춤

작업 규칙은 서버 설계서 4.3과 같다.

- 사이트당 한 번에 한 작업, 잠금은 시간이 지나도 저절로 풀리지 않음
- 작업 키 `레시피:날짜:회차`, 트랜잭션으로 한 번만 생성
- **놓친 일정은 몰아서 하지 않음.** 정한 시각 + 30분 안에 시작 못 하면 건너뛰고 보고
- 시동 명령은 10분 지나면 만료(크롬 지킴이 5분 + 헤드비서 탭 복귀 시간), 23:30~00:30 시작 금지(PDF 날짜 폴더)
- 재시도: 읽기 1회, 화면 채우기는 `reset` 뒤 1회, **`commit`·`printGo` 절대 안 함**, 등록은 1회(`pkAppendMerge` 가 중복 차단)
- ★ 단계는 의도를 먼저 Firebase 에 기록하고, 기록 성공 뒤 한 번 누르고, 결과를 기록. 크롬·PC 가 중간에 꺼져 의도만 남아 있으면 **`unknown` 잠금, 대표님 해제 전까지 그 사이트 작업 금지**

**대표님과의 충돌:** 같은 크롬을 대표님도 쓴다.

- `ez_split.html` 은 잠금을 읽어 비서 작업 중이면 ②·③ 버튼을 막는다.
- 반대로 대표님이 페이지에서 작업 중이면(`ezHelperState` 또는 잠금) 비서는 시작하지 않고 보고한다.
- 비서 탭 맨 위에 「비서 작업 중 — 탭을 닫거나 이지어드민에서 로그아웃하지 마세요」 표시.
- 진행 중 탭을 닫으면 `beforeunload` 경고가 뜬다(지금 도우미에 이미 있음). 그래도 닫히면 `unknown` 처리.
- 작업 탭은 비서 전용 창에 모아, 대표님의 평소 탭과 섞이지 않게 한다.

### 4.3 업무 레시피 `ez_daily`

| # | 단계 | 사용하는 것 | 멈추는 경우 |
|---|---|---|---|
| 0 | 사전 점검 | 5.1 | 어긋남 |
| 1 | 검색·읽기 | `search` | 줄 수 불일치, 로그인 끊김 |
| 2 | 분할 계산 | `Z.planExisting`, `boxes` | 확인 필요 있음 |
| 3 | 채우기 | `Z.fillPayload`, `fill` (묶음 단위로 나눠 호출) | `skipped` 1건 이상 |
| 4 | ★ 일괄합포제외 | `commit { auto:true, lockUnpack:true }` | 오류·실패 목록 |
| 5 | 반영 대조 | `search`, `Z.verifyAfter` | 안 된 묶음 |
| 6 | 공급처별 미리 보기 | `printPrep` | `problems`, 상한 |
| 7 | 승인 또는 통과 | 5.2 | 승인 없음 |
| 8 | ★ 송장 부여 | `printPrep` → `printGo` → `printStatus` → `printEnd` | 건수 변동, `Z.printState` ≠ done |
| 9 | 수집·등록 | 피킹이지 탭 `PK_AGENT.collect()` | 수 불일치, 못 여는 PDF |
| 10 | 보고: 「인쇄 준비 완료」, 건수·특이사항 | `secretary/jobs` | — |

여기서 레시피가 끝난다. 다음은 작업자가 피킹이지를 열어 인쇄를 누르는 일이다. 중복 인쇄는 지금의 송장번호 단위 선점 트랜잭션이 막는다.

필요한 코드 변경 (작게):

| 파일 | 변경 |
|---|---|
| `ez_helper.js` | **명령 변경 없음.** opener 로 연결되므로 지금 코드 그대로 동작하는지 P1 에서 확인 |
| `ez_job.js` (신규) | 화면 없는 흐름 제어. `runCommit`·`runPrint` 의 순서와 점검을 옮기되 사람용 `confirm` 대신 승인 규칙 사용. `ez_split.html` 은 안정될 때까지 그대로 두고, 이후 같은 모듈을 쓰게 합침 |
| `picking_ez.html` | `?agent=1` 일 때 `PK_AGENT.collect()` 로 `pkCollectRun` 결과를 돌려줌 (`added`, `dupList`, `dupPrinted`, 파일 수). 이 모드의 `alert`·`confirm` 은 기록 후 거절 |
| `secretary.html` (신규), 확장 폴더 `tools/secretary_ext/` | 위 설명대로 |
| `database.rules.json` | `secretary/*` 슈퍼관리자 전용 |
| `functions-*` | `secretaryWatch` 예약 함수 |

**도우미 판 고정:** 헤드비서는 허용된 `VER` 만 실행한다. 도우미가 새로 배포되면 무인 실행을 멈추고 보고한다. 낮 배포가 그날 송장을 바로 건드리지 않게 하기 위해서다.

### 4.4 작업 속도: 사람보다 빠르지 않게

`pace.js` 로 모든 사이트 요청을 한 줄로 세워 간격을 지킨다.

| 동작 | 최소 간격 (임시값, P7 실측으로 조정) |
|---|---|
| 검색·조회 | 앞 요청이 끝난 뒤 5초 |
| 화면 채우기 | 묶음당 3초 (346묶음이면 약 17분) |
| 페이지 이동·창틀 열기 | 3초 |
| 로그인 점검 | 10분 |
| 송장 부여 진행 확인 | 2초 (화면 안의 값만 읽어 서버 요청 없음) |
| 동시 요청 | 사이트당 항상 1개 |

- 사이트가 오류·지연으로 답하면 재촉하지 않고 멈춘다.
- **탐지를 피하려는 것이 아니다.** 사이트에 부담을 주지 않으려는 것이므로 무작위 흉내는 넣지 않고 정해진 간격만 쓴다.
- 지금 `fill` 은 묶음을 쉬지 않고 처리한다. 레시피는 한 번에 한 묶음만 보내 간격을 둔다.

### 4.5 로그인 만료

1단계 기본은 **알림**이다.

- 업무 직전과 운영 시간 10분마다 비서 탭에서 읽기로 점검한다. 이지어드민은 로그인 창 표시 여부, 이벗은 조회 응답이 HTML 인지 본다.
- 끊기면 그 사이트 작업을 시작하지 않고 전담비서 페이지 🔑 + 크롬 알림(9장 4번 결정에 따라 폰 알림 추가).
- 대표님이 평소처럼 로그인하면 다음 점검에서 자동으로 🟢.

자동 재로그인은 **선택 사항**이고 P3 를 통과해야 켠다.

- 크롬 비밀번호 저장이 칸을 채운 경우에만, 확장이 로그인 버튼을 **한 번** 누른다. 비밀번호를 읽거나 저장하지 않는다.
- 크롬은 사람 동작 전에는 채운 비밀번호를 페이지에 넘기지 않을 수 있어 안 될 가능성이 있다.
- 실패, 캡차, 기기 인증, OTP 가 하나라도 나오면 멈추고 알린다. 다시 시도하지 않는다.

### 4.6 전담비서 페이지 (`secretary.html`, 슈퍼관리자, 폰 우선)

보기 전용이 아니다. 폰 첫 화면의 주인공은 **시동 버튼**이다. PC 에서도 같은 페이지를 쓴다.

**시동 흐름:**

| 순서 | 폰 화면 | 뒤에서 하는 일 |
|---|---|---|
| 1 | 비서 카드: 이름, 🟢 상시 컴퓨터, 🔑 로그인, 기간 | 생존 신호를 읽음 |
| 2 | **시동 버튼을 길게 누름** (주머니 속 오작동 방지) | `commands` 에 `{ type:'start', secretary, by, at }` |
| 3 | 「시동 거는 중」 → 60초 안에 「시동 걸림」 | 헤드비서가 받았다고 표시, 작업 생성 |
| 4 | 단계별 진행 막대 | 로그인 점검 후 레시피 진행 |
| 5 | 승인 단계라면 건수와 ✅ | 5.2 |
| 6 | 「인쇄 준비 완료」 건수·특이사항 | 작업 종료 |

시동을 막거나 멈추는 경우:

- **상시 컴퓨터 🔴** → 버튼을 끄고 「상시 컴퓨터가 꺼져 있습니다」 표시
- 🟢 인데 60초 안에 응답 없음 → 「응답 없음」. 10분 뒤 만료되며 나중에 저절로 실행되지 않음
- 로그인 풀림 → 시작 안 함, 🔑 안내. 대표님이 현장 또는 원격 접속으로 로그인 후 다시 시동
- 멈춘 작업·`unknown` 잠금이 있음 → 🔓 사유 입력 해제 전까지 시동 불가
- 같은 날 앞 작업이 정상 완료면 다음 시동은 새 회차. 물량이 없으면 0건으로 정상 종료

시동은 「시작」 의사일 뿐, 승인 단계의 ✅ 를 대신하지 않는다. 건수를 보기 전에 누른 것이기 때문이다. 기간 기본값은 **마지막 정상 완료 날짜 ~ 오늘**이고 카드에 보여 주며 시동 전에 바꿀 수 있다. 어느 PC·폰에서 눌러도 같다(지금 `ezSplitFrom` 은 그 PC에만 저장돼 있어 Firebase 로 옮긴다).

그 밖의 화면:

| 영역 | 내용 |
|---|---|
| 특이사항 | **맨 위 고정.** 멈춘 이유, 놓친 일정, 해야 할 일 |
| 상시 컴퓨터 | 🟢 켜짐 / 🔴 N분째 소식 없음, 크롬·확장·도우미 판·이지에이전트·프린터·폴더 권한 |
| 사이트 | 이지어드민·이벗 로그인 상태 |
| 일정 | 요일·시각·회차, 켜기/끄기, 단계(점검만/승인/자동). 시동과 같은 작업을 일정이 거는 것 |
| 기록 | 날짜별 결과 |
| 조작 | ⏸ 전체 멈춤, ✅ 승인, 🔓 잠금 해제(사유 필수) |
| 캐릭터 | 뒤 단계. 데이터는 비서 단위로 나눠 둠 |

`commands` 는 규칙으로 슈퍼관리자만 쓰고, 정해진 종류만 받는다. 임의 코드를 실행하는 경로는 없다.

```
secretary/
  runner               { id, host, ts, ver, helperVer, agentVer, ready:{...} }
  sites/{site}         { state, checkedAt, msg }
  schedules/{id}       { recipe, days, times, enabled, mode, caps }
  jobs/{jobKey}        { state, trigger, by, at, steps, counts, intent, notes }
  locks/{site}         { jobKey, runnerId, at }
  control              { pause, by, at, why }
  commands/{id}        { type, jobKey, by, at, status }
  approvals/{jobKey}   { hash, count, by, at }
```

- 수령자 이름·주소·전화번호는 올리지 않는다.
- 폰에서 시동·✅ 승인·⏸ 멈춤을 누르면 Firebase 로 헤드비서 탭에 실시간 전달된다.
- `secretaryWatch` 는 헤드비서 탭이 꺼져도 돈다. 일정 시각이 지났는데 작업이 없거나 `runner.ts` 가 멈추면 특이사항에 기록한다.

### 4.7 작업자별 송장 배정 (새 기능, 뒤 단계)

**1단계에서 만들지 않는다.** 시동부터 보고까지 첫 비서가 안정된 뒤 추가한다. 다만 1단계가 이것을 막지 않게 경계만 정해 둔다.

지금 있는 것: 그룹 인쇄의 「주문처 우선출력」 고르기, 송장번호 단위 인쇄 선점. 작업자별로 나누는 기능은 없다.

뒤 단계의 방향:

- **비서가 나눈 결과를 만들고, 인쇄는 작업자가 누른다.** 작업자 화면은 자기 몫만 보여 준다.
- **나눔은 보기 필터다.** PDF·송장 목록·인쇄 기록은 바꾸지 않고 `picking_ez/assign` 에 규칙만 둔다. 잘못 나눠도 관리자 「전체 보기」로 바로 인쇄할 수 있다.
- **중복 방지는 그대로.** 배정이 어떻게 되든 지금의 선점 트랜잭션이 마지막 안전장치다.
- **어디에도 안 맞는 송장은 「미배정」** 으로 관리자 화면 맨 위에 올린다. 조용히 아무에게나 주지 않는다.
- 나누는 기준은 대표님 결정(9장 6번). 결정 뒤 별도 설계서를 쓴다.

## 5. 자동 진행 조건과 멈춤 조건

### 5.1 ★ 전 점검

전부 만족해야 한다. 서버 설계서 5.1 표에 다음을 더한다.

- 헤드비서가 등록된 PC, 런너 잠금 소유
- 이 PC 전원 연결 중(`navigator.getBattery`, 지원될 때). 배터리면 멈춤
- 대표님 수동 작업 진행 중 아님
- 프린터 점검: 도우미의 이름 검사(`BIXOLON SLP`)를 쓴다. 웹 페이지는 드라이버를 볼 수 없으므로, 실제 프린터 이름이 그대로 `BIXOLON` 으로 바뀌는 일이 없게 **대표님이 관리**한다. 이 차이는 서버 단계에서 `Get-Printer` 로 메운다

### 5.2 단계별 도입

### 5.3 PC 가 꺼지거나 잠들 때

- 일정 시간대에는 절전하지 않게 한다. **대표님이 전원 설정을 바꾸는 항목**이고, 시험 뒤 적용한다.
- **외부에서 시동을 걸려면 일정 시간대만 해제로는 부족하다.** 상시 컴퓨터는 절전을 끄고, 가능하면 정전 뒤 자동 켜짐(BIOS)과 윈도우 자동 로그인 여부를 함께 정한다. 절전 중인 PC 는 폰에서 깨울 수 없다고 보고 🔴 로 표시한다.
- 절전에서 깨면 헤드비서가 시간 차이를 보고 놓친 일정을 건너뛴 뒤 보고한다.
- 노트북 뚜껑을 닫아도 잠들 수 있다. 일정 시간대에는 전원을 연결하고 열어 둔다.
- 건수 상한: 회차 합계 3,500건 임시값(서버 설계서 5.3 근거).

### 5.4 진행 중 멈춤

서버 설계서 5.4 전부 + 탭 닫힘, 크롬 재시작, 절전 복귀, 폴더 권한 잃음.

## 7. 작업 순서

첫 비서 한 명을 시동부터 보고까지 완성하는 것이 우선이다.

1. **실제 출력 검증:** P0 기록 쌓기, 약관 확인, 대표님 결정 (9장)
2. **헤드비서와 시동 페이지:** 확장·지킴이·헤드비서 탭·전담비서 페이지 → P1·P1b·P2·P4·P5
3. 이지어드민 비서 A 단계 (송장 없음) → P3·P7·P8, 피킹이지 연결 → P6
4. B 단계 → P9, 안정되면 공급처별로 C
5. **일정 실행:** 시동과 같은 작업을 정해진 시각에 건다
6. **비서 늘리기:** 이벗 반품 비서, 업체별 확장
7. **작업자 화면:** 작업자별 송장 배정(4.7), 캐릭터
8. **서버 검토:** 8장 조건이 생기면

## 8. 서버로 옮길 때

다음 중 하나가 생기면 서버 설계서를 다시 꺼낸다.

- 절전·재부팅·대표님 사용과 부딪혀 일정을 자주 놓침
- 이 PC 없이 대표님이 외부에 오래 나가 있어야 함
- 비서 업무가 늘어 탭과 대표님 작업이 자주 부딪힘

이 설계의 `ez_job.js`·`pace.js`·`secretary/*`·전담비서 페이지는 서버에서도 그대로 쓴다. 바뀌는 것은 시작 방식(확장 → Playwright)과 로그인(대표님 → 전용 계정)이다.

## 9. 대표님 결정 사항

순서대로 하나씩 확인한다. 괄호는 답을 받기 전까지 쓰는 권장값이다.

1. 자동 분할 기준 (「기존대로」 고정, 처음 보는 구성이 있으면 멈춤)
2. 최종 목표: 완전 자동인가, 승인 유지인가 (B 승인으로 시작, 공급처별로 C)
3. 회차·시각과 건수 상한 (시각은 대표님 지정, 상한 3,500건)
4. 멈췄을 때 폰 알림 수단. 페이지를 안 보고 있을 때도 알아야 하는가 (1차 페이지 + 크롬 알림, 폰 푸시는 이후 결정)
5. 상시 컴퓨터를 어느 것으로 할까, 절전을 꺼도 되나 (이 PC TOOZ-GRAM, 절전 끔. 다른 장비면 이지에이전트·가상 프린터 설치 필요)
6. 작업자에게 송장을 나누는 기준: 업체별, 상품별, 사람별 중 무엇인가. 작업자는 어떻게 구분하나 (뒤 단계 4.7 의 입력. 권장값 없이 대표님 현장 방식을 먼저 들음)

## 10. 이번에 하지 않는 것

- 구현, 실제 송장 부여, 서버 구입
- 스토어 수집기 변경 (TOOZ-GRAM 설치·실행 금지 유지)
- 비서 캐릭터, 폰 푸시 알림
- 작업자별 송장 배정 구현 (4.7 은 경계만)
- 이벗 업무 레시피 (로그인 점검까지만)

## 11. 다시 시작할 때

대표님 사정으로 작업이 보류됐다. 돌아오면 이 순서로 잇는다. 아직 받은 결정 답은 없다.

1. 물량이 있는 날 지금 화면으로 합포제외와 송장출력을 끝까지 실행한다 (P0).
2. 자동수집에 PDF 가 빠짐없이 들어오는지 확인한다.
3. 9장 질문을 1번부터 하나씩 답한다.
4. 이지어드민·이벗 약관과 캡차·추가 인증을 확인한다.
5. 그 뒤 구현 계획을 쓴다. 이 문서는 아직 구현 승인을 받지 않았다.
