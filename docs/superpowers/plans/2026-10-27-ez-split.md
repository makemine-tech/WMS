# 곡물도감 합포 분할 (이지어드민 비서 1호) 작업 계획

> **For agentic workers:** REQUIRED SUB-SKILL: Use superpowers:subagent-driven-development (recommended) or superpowers:executing-plans to implement this plan task-by-task. Steps use checkbox (`- [ ]`) syntax for tracking.

**목표:** 이지어드민 곡물도감 주문을 우리 페이지에서 막대 하나로 분할 시뮬레이션하고, 도우미가 이지어드민 일괄합포제외 화면에 채워 넣는다 (확정은 사람이).

**구조:** 계산은 화면과 떨어진 `ez_split_calc.js`(브라우저·Node 공용)에 모으고 Node 로 시험한다. 이지어드민 탭의 `ez_helper.js` 가 표를 읽고 채우며, `ez_split.html` 과 postMessage 로만 이야기한다 (이벗 도우미 `ebut_helper.js` ↔ `star_return.html` 과 같은 틀). 포장비는 정산 엔진에서 `p9_fee.js` 로 꺼내 둘이 같이 쓴다.

**기술:** 순수 JS(ES5 스타일, 기존 파일과 같게), Firebase Realtime DB(compat SDK, `wms_access.js` 가 초기화), Node 24 `node:test`.

**설계서:** `docs/superpowers/specs/2026-10-27-ez-split-design.md`

## 공통 규칙

- 호스팅 공개 폴더는 `main/` — 시험 파일은 공개되지 않게 `tools/tests/` 에 둔다. 실행: `node --test tools/tests/`
- 공용 JS 는 `settle_stmt.js` 처럼 `if (typeof window !== 'undefined') window.X = api; if (typeof module !== 'undefined') module.exports = api;`
- 새 페이지: `<script src="/wms_access.js" data-page="ez_split" data-floor="2"></script>` + `/mm_copy.js`, `wms_pages.js` 에 등록.
- Firebase 경로: `wms_sync/groups/{gid}/ez_split/…` (그룹 쓰기 권한이 이미 `wms_sync/groups/$gid` 에 있어 규칙 변경 없음). 박스 기록은 `wms_sync/groups/{gid}/picking_ez/boxes` 읽기만.
- 화면 글·안내는 전부 한국어. 업체에 보이는 이름 규칙과 무관(내부 화면).
- 이벗 도우미와 같은 원칙: 비밀번호·키 없음, makewon.com(및 makechango-wms.web.app·localhost)에서 온 요청만 받음.
- WMS 작업은 커밋 후 main 푸시·배포까지 진행(대표님 원칙). 단 Task 7 의 「일괄합포제외」 실행은 절대 시험하지 않는다.

## 검토 때 특히 볼 것

1. **이지어드민 표가 여러 쪽으로 나뉘어 일부만 읽힘** → `read` 가 화면의 전체 건수(`n / N`)도 돌려주고, 페이지는 읽은 줄 수와 다르면 빨간 경고 + 채우기 막음. (Task 7·8)
2. **같은 묶음에 같은 상품코드가 두 줄** (product_seq 다름) → 모든 계산·채우기는 `product_seq` 기준. (Task 2 시험)
3. **규칙에 안 맞는 새 상품** (입수도 없고 소형 목록에도 없음) → `cls.kind='unknown'`, 그 주문은 손대지 않고 「확인 필요: 모르는 상품」. (Task 2 시험)
4. **읽은 뒤 이지어드민에서 주문이 바뀜** → 도우미가 채우기 직전 다시 읽어 묶음·상품·수량 대조, 다르면 건너뛰고 이유. (Task 7)
5. **수량 0 줄·옵션 있는 줄** → 수량 0 은 무시, 옵션이 있으면 「확인 필요: 옵션 있음」(피킹이지 상품명과 다를 수 있음). (Task 2 시험)
